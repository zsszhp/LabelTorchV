## 1. 文档目标

本文件用于锁定 LabelTorchV 当前阶段的唯一执行方向，确保不同模型在接手项目时，能够按照同一目标、同一优先级、同一边界推进工作，避免方向漂移、过早铺 UI、或者在 MVP 闭环未稳定前扩散范围。

本文件是当前阶段的总控文档，优先级高于普通实现说明文档。执行时需要结合以下文档共同参考：

- `docs/blueprint.md`
- `docs/architecture.md`
- `docs/preflight_checklist.md`
- `reference/Dihuge DLTools/gemini-code-1780391652706.html`
- `docs/UI像素级复刻专项规范.md`
- `docs/里程碑验收与执行清单.md`

## 2. 当前阶段的最高目标

当前阶段采用 `MVP+` 路线，目标分两层，先业务闭环，后 UI 完整复刻。

### 2.1 第一优先级：打通并稳定核心闭环

必须优先保证以下链路稳定可用：

1. 导入数据集
2. 数据集扫描与校验
3. 数据划分或生成训练快照
4. 配置训练参数
5. 启动训练
6. 支持 `YOLOv8 目标检测训练`
7. 支持 `异常检测训练`
8. 导出 `pt`
9. 导出 `onnx`
10. 导出后执行验证

这一条链路稳定之前，不进入真实 UI 功能填充阶段。

### 2.2 第二优先级：像素级复刻最终 UI

UI 的最高参考源不是 PDF，也不是 Markdown 草稿，而是：

- `reference/Dihuge DLTools/gemini-code-1780391652706.html`

该 HTML 文件代表当前阶段 UI 视觉和布局的最高权威参考。执行复刻时：

- 优先参考 HTML 的结构、层次、比例、状态色、边框、阴影、发光、按钮风格、面板分区
- PDF 和 Markdown 仅作为补充语义说明
- 允许基于 Qt/QML 渲染差异做微调
- 不允许偏离整体视觉语言和页面组织方式

---

## 3. 已锁定的用户决策

以下决策已经明确，后续模型执行时不得擅自改写：

1. 当前阶段走 `MVP+`
2. 异常检测属于当前阶段范围，保留并继续完善，不丢弃既有工作
3. `匹配` 页面当前阶段不做
4. UI 要完整做完，但可以分步推进：
   - 先复刻视觉和布局
   - 再补弹窗、按钮、交互
   - 再接页面之间的数据传递和状态流转
5. 图标和视觉基础设施采用行业最优做法
6. UI 复刻标准为高度贴近参考稿的 `B 级标准`：布局比例、按钮尺寸、阴影、间距、状态色、发光效果都尽量贴近
7. 当前真实训练支持锁定 `YOLOv8 detect + anomaly`
8. 当前导出链路锁定 `pt + onnx`
9. 数据集流程按完整流程建设，不做只够演示的半成品
10. 执行管理方式采用 `按里程碑验收`

---

## 4. 当前阶段明确不做的事情

为避免范围失控，当前阶段以下事项只允许保留扩展位，不作为主交付目标：

1. `匹配` 页面
2. 完整的 OBB 真实训练闭环
3. 完整的分类训练闭环
4. 完整的标注引擎交付
5. 辅助标注正式可用版本
6. 增量训练完整产品化
7. TensorRT、TFLite、Engine 等完整导出闭环
8. Ubuntu 交付级兼容

说明：

- 这些能力可以在结构上预留
- 可以保留入口、壳子、状态位、数据结构
- 当前阶段不以这些能力的完整可用为验收门槛

## 5. 唯一正确的执行顺序

任何模型接手本项目，都应严格遵循以下执行顺序：

### 阶段 A：现状审计与断点盘点

目标：明确当前代码中哪些链路已通、半通、未通。

必须完成：

1. 盘点 C++ Service 与 Model
2. 盘点 QML 页面完成度
3. 盘点 Python 后端命令处理器完成度
4. 盘点训练、导出、异常检测的实际可运行状态
5. 盘点数据库 Schema 与实际落库逻辑是否一致
6. 输出断点清单与风险清单

### 阶段 B：MVP+ 业务闭环修复

目标：优先把核心训练与导出链路跑稳。

必须先修复：

1. 项目创建与打开
2. 数据集导入与扫描
3. 类别信息和样本元数据写入
4. 数据划分与训练快照
5. 训练任务状态管理
6. YOLOv8 训练
7. 异常检测训练
8. 导出与验证

### 阶段 C：硬件兼容与稳定性强化

目标：保证 `NVIDIA 30/40/50` 和 `CPU-only` 场景具备可执行路径。

必须覆盖：

1. GPU 探测
2. CUDA 状态判断
3. CPU 自动降级
4. 训练中断恢复
5. 冷启动残留任务修复
6. 友好的错误提示与状态落库

### 阶段 D：UI 设计系统与组件层建设

目标：建立像素级复刻所需的统一基础设施。

必须先做：

1. 主题令牌统一
2. 统一图标系统
3. 统一按钮、输入框、卡片、弹窗、状态灯
4. 统一分栏与分割器
5. 顶栏、过滤栏、底部状态区框架

### 阶段 E：UI 空壳完整复刻

目标：页面先做到视觉、布局、静态交互完整。

执行要求：

1. 完成所有目标页面的静态结构
2. 完成主要弹窗与菜单
3. 完成状态态样式：默认、悬浮、激活、禁用、错误、加载
4. 页面内可用假数据承载视觉状态

### 阶段 F：UI 与真实服务接线

目标：把壳子接到真实数据流和状态流。

必须完成：

1. 页面状态模型统一
2. 按钮接真实服务
3. 弹窗接真实提交逻辑
4. 页面之间状态流转
5. 日志、任务、告警与后端事件联动

### 阶段 G：功能填充与产品补强

目标：在用户确认 UI 方向无误后，逐页补齐业务能力。

## 8. UI 执行原则

### 8.1 最高视觉参考

- `reference/Dihuge DLTools/gemini-code-1780391652706.html`

### 8.2 视觉复刻原则

1. 先复刻顶层布局和比例
2. 再复刻组件样式
3. 再复刻局部细节与状态
4. 最后接真实数据

### 8.3 技术实现原则

1. 优先建立可复用的基础组件
2. 优先使用统一 SVG 图标资源
3. 所有颜色、间距、圆角、阴影、字体都走主题系统
4. 所有分栏支持拖拽调节
5. 所有页面保留空态、加载态、错误态、禁用态

### 8.4 严禁事项

1. 严禁为了赶进度直接在页面中大量硬编码样式
2. 严禁在 MVP 链路未稳定前大量填充页面业务细节
3. 严禁每个页面自造一套交互风格
4. 严禁偏离参考 HTML 的整体视觉语言

---

## 9. 业务闭环执行原则

### 9.1 数据集导入

必须覆盖：

1. 图片扫描
2. 标签配对
3. 异常记录
4. 类别信息读取
5. 样本数量统计
6. 入库

### 9.2 训练快照

必须保证：

1. 训练永远基于不可变快照
2. 快照与原始数据集状态隔离
3. 快照可追溯到训练运行

### 9.3 训练运行

必须具备：

1. 启动前校验
2. 状态流转
3. 日志事件流
4. 指标回传
5. 失败事件
6. 停止事件
7. 冷启动修复

### 9.4 导出验证

必须保证：

1. 导出产物路径可追踪
2. 导出参数可追踪
3. 导出后自动验证
4. 验证结果可持久化

## 10. 硬件兼容目标

本阶段硬件兼容目标明确如下：

1. 支持 NVIDIA 30 系列 GPU
2. 支持 NVIDIA 40 系列 GPU
3. 支持 NVIDIA 50 系列 GPU
4. 支持无 GPU 的 CPU-only 设备训练

执行要求：

1. 启动时完成环境探测
2. UI 中展示设备状态
3. 训练前给出设备建议
4. GPU 不可用时可直接降级到 CPU
5. 显存不足时给出可执行的 batch 建议
