# LabelTorchV 里程碑验收与执行清单

> 版本：1.0
> 日期：2026-06-08
> 状态：执行中

---

## 1. 文档用途

本文件将当前阶段工作拆成可验收的里程碑，供任何模型按顺序执行。每个里程碑都包含：

1. 目标
2. 必做项
3. 产出
4. 验收标准
5. 后续准入条件

执行原则：

- 未通过当前里程碑验收，不进入下一个里程碑
- 用户需要看到每个里程碑的完成结果和剩余问题

---

## 2. 里程碑总览

### M0：现状审计与差距清单

目标：摸清当前代码基础。

必做项：

1. 盘点 `src/features/project`
2. 盘点 `src/features/dataset`
3. 盘点 `src/features/training`
4. 盘点 `src/features/export`
5. 盘点 `backend/labeltorch_backend/handlers`
6. 盘点 `backend/labeltorch_backend/adapters`
7. 盘点现有 QML 页面完成度
8. 盘点测试覆盖

产出：

1. 当前能力矩阵
2. 缺失能力列表
3. 风险清单

验收标准：

1. 能明确说清楚哪些功能已通
2. 能明确说清楚哪些功能是假实现或半实现
3. 能明确说清楚当前最优修复顺序

准入下一阶段条件：

1. 差距清单清楚
2. 用户认可后续修复顺序

---

### M1：项目与数据集基础链路修复

目标：让训练前置链路可靠。

必做项：

1. 项目创建
2. 项目打开
3. 项目路径初始化
4. 数据集导入
5. 数据扫描
6. 标签配对
7. 样本信息入库
8. 数据异常记录
9. 基础样本统计

产出：

1. 可导入的数据集页面状态
2. 数据样本与元数据记录

验收标准：

1. 至少一套 YOLO 检测数据能成功导入
2. 至少一套异常检测数据能成功导入
3. 扫描异常能在系统中被标识

准入下一阶段条件：

1. 训练前的数据输入稳定

---

### M2：快照、划分与训练启动链路修复

目标：让训练可以从正确的数据状态启动。

必做项：

1. 数据划分
2. 快照创建
3. data manifest 生成
4. data yaml 或训练配置生成
5. 训练配置组装
6. `train.start` 调用链打通

产出：

1. 可复用的训练输入快照
2. 训练启动前检查机制

验收标准：

1. 检测训练可启动
2. 异常检测训练可启动
3. 配置和快照能追溯到训练记录

准入下一阶段条件：

1. 训练至少能稳定启动

---

### M3：训练运行、事件回流与稳定性修复

目标：让训练过程具备可靠状态管理。

必做项：

1. `running/stopped/failed/succeeded` 状态流转
2. 日志回流
3. 指标回流
4. 停止训练
5. 进程中断修复
6. 冷启动残留状态修复

产出：

1. 训练可观测
2. 训练异常可恢复

验收标准：

1. 训练状态能在 UI 或数据层正确呈现
2. 异常退出后不会长期残留错误状态

准入下一阶段条件：

1. 训练过程稳定可观测

---

### M4：导出与验证闭环修复

目标：让模型训练结果真正可交付。

必做项：

1. `pt` 导出登记
2. `onnx` 导出登记
3. `artifact.verify` 验证
4. 导出结果落库
5. 导出失败状态处理

产出：

1. 模型导出产物
2. 验证结果

验收标准：

1. 检测模型可导出 `pt` 和 `onnx`
2. 异常检测模型具备当前阶段约定的导出与验证路径
3. 验证结果可追踪

准入下一阶段条件：

1. 核心闭环完整成立

---

### M5：硬件兼容与环境自检

目标：覆盖多种本地设备条件。

必做项：

1. GPU 探测
2. CUDA 检测
3. 设备列表输出
4. CPU 降级
5. 显存不足提示
6. 设备选择策略

验收标准：

1. 有 GPU 时能正确识别
2. 无 GPU 时仍可训练
3. 训练前能给出设备状态

准入下一阶段条件：

1. 设备兼容能力满足本阶段要求

---

### M6：UI 基础设施建设

目标：为像素级复刻铺底。

必做项：

1. 主题令牌
2. 图标系统

4. 分栏与分割器
5. 弹窗基础模板
6. 顶栏和过滤栏框架

验收标准：

1. 新组件可被多个页面复用
2. 视觉风格统一

准入下一阶段条件：

1. 复刻页面时无需再临时造通用组件

### M7：UI 空壳完整复刻

必做项：

验收标准：

1. 页面结构接近参考 HTML
2. 状态风格统一
3. 用户确认方向正确

准入下一阶段条件：

1. 用户明确确认 UI 架子通过

### M8：UI 接真实数据与服务

目标：让 UI 从外壳变成真实可操作界面。

---

## 3. 每个里程碑都必须验证的横向项

无论处于哪个里程碑，都必须检查：

1. 是否破坏现有可用能力
2. 是否引入 UI 风格分裂
3. 是否引入状态不一致
4. 是否有未处理错误路径
5. 是否有明显的假交互占位没有标识清楚

---

## 4. 推荐执行节奏

1. 先做 `M0` 到 `M5`
2. 再做 `M6` 与 `M7`
3. 用户确认 UI 架子后，再做 `M8` 与 `M9`

---

## 5. 当前阶段的总验收口径

当前阶段完成的标准是：

1. `MVP+` 核心闭环稳定
2. 支持 `YOLOv8 detect + anomaly`
3. 支持 `pt + onnx` 导出与验证
4. 支持 `GPU + CPU-only` 训练路径
5. UI 达到高保真空壳复刻标准
6. UI 骨架确认后具备继续填充功能的稳定基础
