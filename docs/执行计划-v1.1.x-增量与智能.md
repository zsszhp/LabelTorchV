# 执行计划：v1.1.x 增量与智能

> 版本：1.0
> 日期：2026-09-29
> 状态：待执行
> 前置基线：v1.0.x 标注引擎正式版收口后
> 执行环境：主开发在 GPU 机进行（训练/续训/对比曲线必须真实跑通），UI 与服务层可在 CPU 机并行

---

## 1. 目标与非目标

### 1.1 目标

打通「上一版模型 → 辅助标注 → 增量训练 → 对比验收 → 晋级」的数据闭环，让数据闭环在产品内真转起来，具体达成四件事：

1. **增量训练产品化**：从模型中心选 `last.pt` / `best.pt` 一键续训或微调，配套增量数据快照与新旧 run 曲线叠加对比。
2. **主动学习闭环 UI**：难例挖掘页接真实 `active_learning_items` 数据，低置信 / 漏检 / 误检三队列可用，一键送标注并回写。
3. **错误分析报告**：逐类漏检超检排行、混淆矩阵可交互、失败案例可视化，一键导出自包含 HTML 报告。
4. **模型版本治理**：`production` 标签唯一、晋级 / 回滚语义化、精度回归告警。

### 1.2 非目标（本期明确不做）

1. 新增模型家族（SAM、RT-DETR 等）与新任务类型。
2. 主动学习采样策略升级（不确定性采样、委员会投票等），本期只做「队列产品闭环」。
3. 分布式 / 多机训练、云端同步、多人协作。
4. 报告的 PDF 排版引擎（本期交付自包含 HTML，PDF 由浏览器打印导出）。
5. 视频流主动学习、产线在线闭环。
6. 浅色主题、多语言界面。

## 3. 任务分解

工作量单位为人日。编号规则：主任务字母 + 子任务序号。

### 3.1 主任务 A：增量训练产品化

#### A1 续训 / 微调一键入口

- **涉及文件**：
  - `src/features/training/TrainingService.h/.cpp`
  - `src/features/training/qml/TrainingPage.qml`、`ConfigPanel.qml`
  - `src/features/model/ModelRegistry.h/.cpp`（取版本的 best/last 权重路径）
  - `backend/labeltorch_backend/handlers/training.py`
  - `backend/labeltorch_backend/adapters/ultralytics_adapter.py`
- **实现要点**：
  1. 训练配置新增 `resume_from`（权重路径）与 `resume_mode`（`resume` / `finetune`）字段，写入 `config_snapshot_json`，并记录来源 `model_version_id` 与父 `run_id`，保证血缘可溯。
  2. 产品语义区分：选 `last.pt` 走 **续训**（断点续跑，epoch 接续，无断点时按 v0.2.0 既有逻辑明确报错）；选 `best.pt` 走 **微调**（新 run 冷启动，默认更小学习率与更少 epoch，UI 预填）。
  3. `train.start` 载荷透传 `resume_from`，路径走 IPC 白名单校验；适配器映射为 Ultralytics 的 resume 参数 / 微调加载。
  4. TrainingPage 增加「从上一版继续训练」入口：按项目列出 model_versions（含标签与指标摘要），选中后自动带出权重路径与建议超参。
- **验收**：
  1. 选 `last.pt` 续训出新 run，epoch 从断点接续，日志与 `run_metrics` 连续。
  2. 选 `best.pt` 微调出独立新 run，`config_snapshot_json` 中可查到来源版本与父 run。
  3. 权重不存在 / 跨项目路径被拒并给出可读错误。
- **工作量**：3 人日

#### A2 增量数据快照

- **涉及文件**：
  - `src/features/training/SnapshotService.h/.cpp`
  - `src/features/training/qml/SnapshotPage.qml`
  - `backend/labeltorch_backend/handlers/snapshot.py`
- **实现要点**：
  1. `createSnapshot` 新增增量模式：本次新增样本全量入册 + 历史样本按比例采样（按类分层，比例可配，默认 30%），`sample_manifest_json` 记录 `base_snapshot_id` 与采样策略。
  2. 延续哈希冻结：逐样本 imageHash / labelHash 照旧写入，训练前漂移校验（`E_SOURCE_DRIFT`）不放松。
  3. 快照预览区分「新增样本 / 采样样本」标记，列表可按来源过滤。
- **验收**：
  1. 同一数据集两次创建增量快照，manifest 可复现出相同样本集合。
  2. 冻结后篡改样本，续训前校验报 `E_SOURCE_DRIFT`。
  3. 全量快照行为不回归（既有测试全绿）。
- **工作量**：3 人日

#### A3 新旧训练曲线对比

- **涉及文件**：
  - `src/features/model/MetricService.h/.cpp`
  - `src/features/model/qml/ComparePage.qml`、`MetricChart.qml`
- **实现要点**：
  1. 复用 `getMetricHistory` / `compareVersions`，新增「按 run 叠加 epoch 曲线」：mAP50、mAP50-95、box/cls/dfl loss 多轴切换。
  2. 对比卡展示最终指标差值（含涨跌着色：正常绿 / 警告黄 / 退化红）与训练耗时、样本量、快照来源。
  3. 支持从续训 run 一键跳到父 run 曲线。
- **验收**：任选两个 run 可叠加出曲线，指标差值与 `run_metrics` 落库值一致；无数据 run 有空态引导。
- **工作量**：2 人日

### 3.2 主任务 B：主动学习闭环 UI

#### B1 难例队列页接真实数据

- **涉及文件**：
  - `src/features/inference/ActiveLearningService.h/.cpp`
  - `src/features/inference/qml/ActiveLearningPage.qml`
  - `backend/labeltorch_backend/handlers/active_learning.py`
- **实现要点**：
  1. 三队列 Tab（低置信 / 漏检 / 误检）读 `active_learning_items`，分页 + 按优先级 / 置信度 / 类别排序，支持类别与数据集筛选。
  2. `ActiveLearningService` 补齐队列查询接口（分页列表、状态流转），保留既有 `collectLowConfSamples` / `prioritizeQueue` / `queueStats` 链路。
  3. 队列项展示缩略图、原因（`reason`）、优先级、类别，空态走 EmptyState 组件。
- **验收**：重启后队列不丢；三队列数据与落库一致；万条队列滚动不卡顿（分页生效）。
- **工作量**：3 人日

#### B2 一键送标注 → 确认 → 回写

- **涉及文件**：
  - `src/features/inference/ActiveLearningService.h/.cpp`
  - `src/features/inference/AssistedLabelService.h/.cpp`
  - `src/features/inference/qml/ActiveLearningPage.qml`
  - `src/features/annotation/qml/AnnotationPage.qml`
- **实现要点**：
  1. 队列项操作「送标注」：跳转标注页并定位到 `sample_id`，标注保存后经 `annotation_revisions` 留痕。
  2. 确认后复用 `commitConfirmedLabels` 回写 YOLO txt，队列项状态置 `done` 并记录处理时间；拒绝项置 `skipped`。
  3. 批量操作：多选送标注、按阈值批量确认（复用 `confirmAllAboveThreshold`）。
- **验收**：从收集到标注回写全程不出 UI；回写后 txt 与修订记录正确；失败有 Toast 错误提示且不吞错。
- **工作量**：3.5 人日

#### B3 闭环看板

- **涉及文件**：`ActiveLearningPage.qml`、`active_learning.py`（`handle_queue_stats` 扩展）
- **实现要点**：顶部统计条展示「已收集 / 已标注 / 已回写 / 已再训练」四段漏斗，以及各队列积压量；点击数字过滤列表。

### 3.3 主任务 C：错误分析报告

#### C1 逐类漏检超检与失败案例可视化

- **涉及文件**：

- **验收**：失败案例可视化结果与混淆矩阵统计对得上；送标注后队列可见该样本。

- **验收**：点击任一格列出的样本数与单元格数值一致。
- **工作量**：1.5 人日

#### C3 报告导出

- **涉及文件**：`TestingService.h/.cpp`、`ExportService.h/.cpp`（导出目录约定）、`backend/labeltorch_backend/handlers/testing.py`

  2. 输出到 `runs/{taskId}/report/`，文件名含模型版本与日期；报告生成写入 `task_events` 审计。
- **验收**：断网环境双击 HTML 可完整打开；报告内容与页面数据一致。
- **工作量**：2 人日

### 3.4 主任务 D：模型版本治理

#### D1 production 唯一性与晋级 / 回滚

- **涉及文件**：
  - `src/features/model/ModelRegistry.h/.cpp`
  - `src/features/model/qml/ModelPage.qml`
  - `src/core/utils/AuditLog`（接入）
- **实现要点**：
  1. `setTag(versionId, "production")` 改为事务：先摘除同项目旧 `production`，再打新标，保证全局唯一；`baseline` / `best` 标签语义不变。
  2. 新增语义化接口 `promoteModel` / `rollbackModel`：晋级前校验证据（必须有测试运行结论），回滚记录来源版本，两者均写 `task_events` 审计（含前后版本 id）。
  3. ModelPage 增加「晋级 / 回滚」按钮与危险操作二次确认，版本列表徽标区分 production / best / baseline。
- **验收**：同项目同时只存在一个 `production`；回滚后审计可查；并发打标不产生双 production（事务验证）。
- **工作量**：2.5 人日

#### D2 精度回归告警

- **涉及文件**：`ModelRegistry.h/.cpp`、`MetricService.h/.cpp`、`ModelPage.qml`
- **实现要点**：
  1. 晋级时自动对比基线（当前 production，无则对比 baseline）：mAP50-95 下降超过阈值（默认 2 个百分点，可配）触发黄色告警，需勾选「确认接受退化」才能继续；关键指标崩溃（下降超 10 点）红色阻断。
  2. 对比结果（指标差值表）随晋级审计一并落库，可回看。
- **验收**：构造退化模型晋级时告警出现且可阻断 / 可确认；正常晋级无打扰。
- **工作量**：2 人日

## 5. 里程碑拆分（4 周）

> 按 2 条线并行（线 1：训练闭环 A + 治理 D；线 2：主动学习 B + 错误分析 C）折算，总工作量约 25 人日。

|--------|------|----------|----------|

## 6. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| v0.3 压测结论未产出 | 续训默认超参无依据 | A1 不预填强默认值，配置模板后补 |
| v1.0 辅助标注 UI 延期 | B2 依赖落空 | B2 先接后端回写接口做简化审核条，UI 到位后切换复用 |
| 增量采样偏斜导致新旧曲线不可比 | 对比结论误导 | A2 强制按类分层采样并在对比卡标注样本构成差异 |
| 大队列 / 大报告性能 | UI 卡顿 | B1 分页、C3 报告数据量上限（失败案例默认取前 200 条，可配） |
