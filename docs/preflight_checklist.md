## 一、用途

## 二、环境自检

### 2.1 Windows 与工具链

建议确认：

1. Qt 6.11.1 可用
2. MSVC 2022 可用
3. CMake 3.22+ 可用
4. Ninja 可用

建议检查命令：

```powershell
cl.exe
cmake --version
```

### 2.2 Python 环境

建议确认：

1. Python 3.11+
2. `ultralytics` 可用
3. `onnxruntime` 可用
4. `opencv-python` 可用
5. 异常检测依赖按当前阶段需要可用

建议检查命令：

```powershell
python --version
python -c "import ultralytics"
python -c "import onnxruntime"
```

### 2.3 GPU 与 CUDA

建议确认：

1. `nvidia-smi` 可用
2. PyTorch 能识别 CUDA
3. 能拿到 GPU 名称与显存信息

建议检查命令：

```powershell
nvidia-smi
python -c "import torch; print(torch.cuda.is_available()); print(torch.cuda.device_count())"
```

## 四、常见风险检查

### 4.1 路径问题

需要重点检查：

1. 项目路径是否包含中文
2. 项目路径是否包含空格
3. 数据集路径是否包含中文
4. 数据集路径是否包含空格

如果底层训练或导出链路对路径敏感，应在 UI 或 Service 层提前提示。

### 4.2 设备选择问题

需要重点检查：

1. 训练配置是否支持 `cpu`
2. 训练配置是否支持 `cuda:0`、`cuda:1`
3. 是否存在写死设备的情况

### 4.3 训练残留状态问题

需要重点检查：

1. 训练异常退出后数据库状态是否会残留为 `running`
2. 冷启动时是否存在残留修复逻辑

### 4.4 Python 输出阻塞问题

需要重点检查：

1. Python 进程是否启用非缓冲输出
2. 日志和事件是否会卡在缓冲区

### 4.5 GPU 不可用问题

需要重点检查：

1. `environment.check` 是否能正确给出 GPU 不可用状态
2. GPU 不可用时是否能走 CPU 降级路径

## 五、数据库与状态检查

数据库结构以代码中的 `Schema` 定义为准，不在文档里重复维护整份 DDL，避免代码与文档脱节。

执行前应确认：

1. `Schema` 中的表定义和当前代码一致
2. 项目、数据集、快照、训练任务、模型版本、导出产物相关表已覆盖当前阶段需求
3. 状态值命名在 C++、Python、数据库和 UI 之间一致
