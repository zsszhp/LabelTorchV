---

## 一、产品定位回顾

标炬（LabelTorch）是面向工业缺陷检测的本地离线视觉数据治理与模型闭环平台。

核心工作流：导入数据集（图片 + 标签）→ 数据治理 → 标注/辅助标注 → 训练 → 测试评估 → 导出模型（pt/onnx）→ 产线部署

当前 v0.2.0 已达成：
1. 训练闭环稳定可用（YOLOv8 detect + 异常检测）
2. 数据安全与防崩溃收口
3. 导航与 UX 体系成型
4. 绿色包解压即用（CPU 版）
5. 测试与文档基线

## 三、v0.3.x 产线硬化

### 3.1 目标

把「在我的机器上能跑」变成「在客户产线工控机上敢用」。

### 3.2 范围

1. **GPU 版依赖打包**
   - torch CUDA 版（cu121/cu124）纳入绿色包或可选分包
   - 30/40/50 系显卡实测记录
   - GPU 显存预检与 batch 自动建议
2. **安装器交付**
   - IFW binarycreator 实包
   - 代码签名（可选，若无证书则文档说明）
   - 升级/卸载不丢用户项目数据
3. **真实数据压测**
   - 1 万张 4K 数据集导入→浏览→标注→训练→导出
   - 内存/磁盘/耗时基线报告
4. **UI 收尾**
   - CheckPage / AnnotationPage / TestingPage 空态组件化
   - FormField 全量套用
   - 设置项 C++ 桥（Log::setLevel 真生效）
5. **稳定性回归**
   - 崩溃注入测试
   - 断电/杀进程恢复

### 3.3 验收标准

1. 在 30 系与 40 系 GPU 机器上完成一次完整训练
2. 绿色包在干净 Windows 10/11 虚拟机解压即用
3. 万张图滚动 RSS < 1GB，标注切换 < 500ms
4. 所有空态无「纯文字裸提示」
5. ctest / pytest 全绿

### 3.4 详细实施计划

见 `docs/执行计划-v0.3.x-产线硬化.md`

## 四、v1.0.x 标注引擎正式版

### 4.1 目标

标注能力达到 labelme / x-anything 可用水平，OBB 链路贯通。

### 4.2 范围

1. **多边形标注完善**
   - 顶点增删拖拽、吸附、撤销重做
   - YOLO 多边形格式读写闭环
2. **画布体验**
   - 平滑缩放、触摸板/捏合
   - 右键菜单（复制/删除/改类/锁定）
   - 复制上一帧（产线连续帧刚需）
   - 虚拟化大图渲染
3. **OBB 全链路**
   - OBB 标注 → OBB 训练 → OBB 导出验证
   - 数据划分支持 OBB 标签
4. **辅助标注产品化**
   - 批量审核 UI（接 `commitConfirmedLabels` / `retrainFromBatch`）
   - 置信度阈值调节、按类过滤
5. **快捷键与效率**
   - 可配置快捷键
   - 类别颜色/顺序管理
   - 标注统计看板

### 4.3 验收标准

1. 多边形可绘制/编辑/导出/训练
2. OBB 从标注到 onnx 导出全通
3. 辅助标注一次批量确认 100 样本无卡顿
4. 标注效率指标：连续帧复制后单帧标注 < 3 秒

### 4.4 详细实施计划

见 `docs/执行计划-v1.0.x-标注引擎.md`

## 五、v1.1.x 增量与智能

### 5.1 目标

打通「上一版模型 → 辅助标注 → 增量训练」主工作流，让数据闭环真正转起来。

### 5.2 范围

1. **增量训练产品化**
   - 选择上一版模型（last.pt / best.pt）一键续训
   - 增量数据快照（新样本 + 历史样本采样）
   - 训练对比曲线（新旧 run 叠加）
2. **主动学习闭环**
   - 难例队列页接 `active_learning_items` 真实 UI
   - 低置信/漏检/误检三队列
   - 一键「送标注 → 确认 → 回写」
3. **错误分析报告**
   - 逐类漏检/超检排行
   - 混淆矩阵交互
   - 失败案例可视化
4. **模型版本治理**
   - production 标签唯一性
   - 晋级/回滚动作
   - 精度回归告警

### 5.3 验收标准

1. 从 v1 模型一键增量训练出 v2，指标可对比
2. 难例从收集到标注回写全程 UI 完成
3. 生成可导出的错误分析 PDF/HTML 报告

### 5.4 详细实施计划

见 `docs/执行计划-v1.1.x-增量与智能.md`

## 六、v2.0.x 工业落地

### 6.1 目标

满足电池/3C/金属表面缺陷产线的追溯与交付要求。

### 6.2 范围

1. **工业元数据**
   - 批次/料号/工位/相机/条码/缺陷等级
   - CSV/条码旁路导入
   - 按批次筛选与追溯
2. **数据治理视图**
   - 数据血缘图（样本→快照→训练→模型→导出）
   - 质量趋势时序
   - 去重/合并/批量修标签工具
3. **产线交付**
   - IATF 风格审计报告
   - 模型-产线映射（deploy_target）
   - 部署包：onnx + classes.yaml + thresholds + warmup + 推理样例 + 精度报告
4. **多机与协作（可选）**
   - 项目打包/导入同步
   - 只读审计导出

### 6.3 验收标准

1. 按批次可追溯到训练数据与模型版本
2. 导出交付包可直接给集成商
3. 审计报告符合客户质量体系要求

### 6.4 详细实施计划

见 `docs/执行计划-v2.0.x-工业落地.md`

## 八、架构约束（延续）

1. Qt/C++ 主进程 + Python 子进程隔离
2. 训练必须基于不可变快照（哈希冻结）
3. 模型版本可追溯到训练与快照
4. 不可逆操作必须审计（task_events / annotation_revisions）
5. 离线优先，CPU 可降级
6. 禁止 dummy/占位符；错误向上传播
7. 配置写入原子化

## 十、执行原则

1. 每个版本按里程碑验收，未过不进下一阶段
2. GPU 相关验证必须在 GPU 机执行并留测试记录
3. 发现 Bug 先写失败测试再修
4. 每次修改编译验证；一个 commit 只做一件事
5. 版本 tag：`v{major}.{minor}.{patch}`
6. 交互与文档全程中文
