## 一、 系统架构蓝图与技术选型

### 💻 推荐架构设计 (React + Electron + Python Backend)
```
┌────────────────────────────────────────────────────────┐
│              Electron 桌面壳体 (进程管理/本地IO)          │
│  ┌──────────────────────────────────────────────────┐  │
│  │           React + TypeScript + Tailwind          │  │
│  │   ┌───────────────┐           ┌──────────────┐   │  │
│  │   │  UI / 状态管理 │ ◄───────► │  Fabric.js   │   │  │
│  │   │ (Shadcn/Antd) │           │  标注画布     │   │  │
│  │   └───────────────┘           └──────────────┘   │  │
│  └──────────────────────────────────────────────────┘  │
│                           │                            │
│                           │ IPC (stdin/stdout JSON-RPC)│
│                           ▼                            │
│                  Python 离线计算服务                     │
│    ┌──────────────────────────────────────────────┐    │
│    │  Ultralytics (YOLO)  │   Anomalib (异常检测)  │    │
│    └──────────────────────────────────────────────┘    │
└────────────────────────────────────────────────────────┘
```
* **前端框架**：React 18 + TypeScript + Tailwind CSS (现代暗黑工业风)。
* **UI 组件库**：Shadcn UI (现代质感) 与 Ant Design (数据表格与表单)。
* **核心画布**：Fabric.js / Konva.js (支持滚轮缩放、拖拽平移、HBB矩形/OBB旋转矩形绘制)。
* **桌面端打包**：Electron 或者是 Tauri (支持多进程隔离，优雅调配本地 GPU 算力)。
* **本地数据存储**：SQLite 3 (WAL 模式)，用于本地项目、数据集元数据与训练日志的版本化管理。

## 二、 核心功能模块规格说明

### 1. 项目管理 (Project)
* **功能职责**：应用冷启动的唯一入口，管理所有本地训练项目。
* **布局规范**：左中三栏式布局，左侧为操作区，右侧为主内容区。
* **UI 规格**：
  * **左侧操作区**：
    * `新建项目 (New Project)` 蓝色主按钮：点击弹出对话框，输入“项目名称”、“项目描述”、选择“项目路径”（通过 Electron/Tauri 调用本地文件夹选择器）、指定“默认任务类型”（目标检测/异常检测/旋转框检测）。
    * `打开项目 (Open Project)` 灰色次级按钮：点击选择已存在的项目配置文件（`project.json`）。
  * **右侧主显示区**：
    * `最近使用项` 列表：以卡片或表格形式展示最近打开过的项目。
    * 字段要求：项目名称、项目描述、本地绝对路径、最近更新时间。
* **边界与约束**：
  * 新建项目时，系统必须在目标路径下自动初始化物理目录结构：
    ```
    {projectRoot}/
    ├── project.json           # 项目元数据
    ├── data/                  # 导入图像与标注的快照
    ├── models/                # 训练产生的模型权重 (.pt)
    ├── exports/               # 导出的部署模型 (.onnx)
    └── logs/                  # 训练日志
    ```

### 2. 数据集管理 (Dataset)
* **功能职责**：管理、预览、划分本地导入的数据集。
* **布局规范**：三栏布局。左侧栏占 25%，中右侧图库区占 75%，顶部工具栏跨栏居中。
* **UI 规格**：
  * **顶部工具栏**：
    * 按数据集筛选下拉框。
    * 按 Tag 筛选下拉框。
    * 按标签类别筛选下拉框。
    * 文本检索框（支持拼音或文件名模糊搜索）。
    * 已筛选图像数量统计（格式：`已筛选图像: X / 总数 Y`）。
  * **左侧边栏 (自上而下)**：
    * **图库管理**：下拉菜单选择当前主图库，右侧带 `+` 号支持新建图库分区。
    * **数据集列表**：展示数据集名称、可见性眼球开关、删除/添加图标、以及导入进度/数量进度条（如 `100/120` 带有填充底色）。
    * **图像属性展示**：选中某张图像时，显示图像名称、绝对路径、分辨率大小（如 `1920x1080`）、标签实例数、所含类别分布。
    * **Tag 管理**：管理附加在图像上的轻量级属性标签，支持动态分配与删除。
  * **中右侧主区域**：
    * 图片网格展示区（Gallery）：支持懒加载的缩略图网格。鼠标悬浮显示文件名，选中后左侧边栏图像属性区实时更新。
* **边界与约束**：
  * 导入数据集时，后台需启动多线程扫描，验证图片和 txt 标签的配对性，记录并提示异常数据（如“标签坐标越界”、“标签类别与当前体系冲突”）。
  * **引导式类别对齐弹窗 (Guided Class Mapping Dialog)**：当扫描检测到导入的 `classes.txt` 顺序与当前项目定义不一致，或缺失类定义文件时，系统必须自动弹窗列出两者差异，引导用户进行手动拖拽对齐（如：源数据集的类0映射到项目的类2）。导入时系统自动在后台重写坐标的 Class ID 并安全写入数据库，以确保项目内的 Class ID 彻底统一。

### 3. 数据标注 (Annotation)
* **功能职责**：进行高精度的交互式图像标注与修剪。
* **布局规范**：左侧列表（20%）、中央工作画布（60%）、右侧实例与快速切换（20%）。
* **UI 规格**：
  * **左侧边栏**：展示当前数据集树形列表，包含图片切换控件（`◀` `▶`），标注进度条。
  * **中央工作区**：
    * **顶部画布工具栏**：全屏、自适应大小（Zoom to Fit）、矩形画框工具、旋转矩形画框工具、多边形/分割工具、魔棒/笔刷调节滑块、明暗度/对比度调节滑块、隐藏/显示标注开关。
    * **主画布**：支持大分辨率图片流畅缩放、平移。绘制形状时具有高亮辅助对齐线。
  * **右侧边栏**：
    * **实例列表**：展示当前图像上所有标注的对象。字段包含：类别名（带颜色标记）、坐标（X, Y, 宽度, 高度, 面积）。
    * **文件列表**：当前文件夹下的图片微缩略图列表，支持双击快速切换。
* **边界与约束**：
  * 任何画布的编辑必须具备原子写回（Auto-save 或 快捷键强保存）机制，写回时自动创建 `.bak` 备份文件以防意外断电损坏。
  * **AI 辅助标注与逐类别置信度阈值 (Class-Specific Thresholds)**：在进行历史模型预打标时，系统不仅要提供全局置信度调节，还必须允许用户针对每个检测类别设定独立的置信度过滤门槛（例如：低召回特征如“微小划痕”设为 0.35；高置信特征如“孔洞破损”设为 0.70）。生成的预测候选框在画布上以虚线高亮显示，支持快捷键一键批量审核（全部接受/全部拒绝/逐一修改并确认保存）。

### 4. 数据检查 (Inspection)
* **功能职责**：提供标注质量的“漏检”、“错检”、“异常”质检工作流。
* **布局规范**：类似于数据集管理界面。
* **UI 规格**：
  * 左侧栏新增 **“程度图像模式”** 开关与指标面板。
  * **“标签类别”** 统计栏：列出“未标注的图像”数量、以及严重程度等级占比。
  * 主区域仅显示被质检筛选规则过滤出来的“问题图像”，供审核人快速审阅并批量修改。

### 5. 模型训练 (Training)
* **功能职责**：为 YOLO/异常检测模型提供超参配置、流程启动与指标观测。
* **布局规范**：三栏布局。左侧模型列表（20%）、中间配置表单（40%）、右侧网络与数据增强配置（40%）。
* **UI 规格**：
  * **左侧边栏**：展示已配置或历史运行的模型列表，带 `+` 新建配置按钮。每个条目展示状态（空闲、训练中、已完成、失败）。
  * **中间配置区域**：
    * **数据配置**：下拉菜单选择训练数据集、验证数据集。
    * **训练参数**：Epochs（数值输入，如 200）、Batch Size（下拉选择 4/8/16/32/64）、Optimizer（下拉选择 SGD/AdamW/RMSprop）、学习率（数值输入）、计算设备选择（下拉列表显示本地可用 CPU 和 NVIDIA GPU 型号）、模型保存周期。
    * **底部操作**：醒目的“开始训练 / 停止训练”动作按钮。
  * **右侧配置区域**：
    * **网络配置**：选择模型网络结构（如大模型、中模型、小模型，或 YOLOv8n/s/m/l/x）、预训练权重指定、输入图像大小、通道数。
    * **数据增强配置**：平移、旋转、缩放、翻转、明暗度等，每个增强项配有启用 Checkbox 与数值滑块。
* **边界与约束**：
  * 启动训练前，系统必须自动在后台检查数据集是否为空。如果用户选择了 GPU 但本地 CUDA 驱动未加载，应弹出阻塞式提示并提供降级到 CPU 训练的选项。
  * **冷启动自动自检与状态修复**：软件冷启动时，主进程必须自检 SQLite 数据库中处于 `running` 状态的模型训练任务，轮询操作系统的 PID。若该 PID 不存在或已被销毁，系统自动将数据库中的状态修正为 `stopped`，记录“检测到程序异常中断”，并释放任务占用锁，提示并引导用户手动点击“一键断点续训”。
  * **路径清单快照方案 (TXT List Snapshot)**：模型训练启动前所生成的不可变数据集快照，不得直接拷贝图片文件本身（防止浪费磁盘空间和耗时），而是在快照目录下生成 `train.txt` 和 `val.txt` 清单文件，写入对应图片的绝对物理路径，并自动生成指引 YAML 配置文件给 Ultralytics。这在 Windows 下完美避开了拷贝开销和创建符号链接 (Symlink) 时的管理员权限限制。

### 6. 模型测试 (Testing)
* **功能职责**：在测试集上评估已训练模型的泛化性能。
* **布局规范**：上配置面板，下指标与图表看板。
* **UI 规格**：
  * **配置区**：选择测试数据集、选择待评估的权重文件（`.pt` 或者是 `.onnx`）、配置 IoU 阈值、置信度阈值。
  * **数据看板**：
    * 精确率（Precision）与召回率（Recall）的环形仪表盘。
    * PR 曲线（Precision-Recall Curve）的高性能折线图渲染。
    * 混淆矩阵（Confusion Matrix）的热力图展示。

### 7. 模型导出 (Export)
* **功能职责**：转换并导出部署级权重，附带导出完整性验证报告。
* **布局规范**：对称卡片布局。
* **UI 规格**：
  * **导出模型卡片**：选择目标硬件平台（CPU/GPU）、选择测试通过的 `.pt` 文件、选择导出格式（`.onnx` / `.engine`）、配置导出路径，点击“导出模型”。
  * **导出报告卡片**：配置导出质量报告路径，点击“导出报告”，生成 PDF 或 Markdown 格式的训练测试报告（包含训练超参、混淆矩阵、测试集代表性推测图）。
* **边界与约束**：
  * **进阶参数配置面板 (Advanced Export Config)**：导出界面不仅提供一键默认导出，还必须支持进阶选项：
    * 允许用户自定义配置是否启用“动态输入尺寸 (Dynamic Shape)”。
    * 是否启用“Simplifier 简化与拓扑结构优化”。
    * 允许选择“Target Opset 版本”（支持 Opset 11 / 12 / 17 切换），确保能兼容不同老旧版本的 TensorRT/OpenVINO 部署引擎。
  * **自动推理与校验守卫**：导出 ONNX 时，系统后台必须调用内嵌 ONNX Runtime 执行 Dummy Tensor 推理校验。验证成功后，自动在导出目录下生成一份“模型结构与输入输出特征报告”（Markdown 格式，说明具体 Input Name, Shape, DataType 及 Output Nodes，方便下游 C++ 工控机部署人员直观复制）。

## 三、 系统演进边界与硬性约束

1. **完全零环境依赖**：
   * 所有训练底层环境（包括 Miniconda/Python 解释器、PyTorch 依赖、CUDA Toolkit 运行库）必须预先打包。
   * 用户解压即可训练，不得要求用户手动执行 `pip install` 或安装 CUDA 驱动（显卡基础 Driver 除外）。
2. **多显卡与硬件自检**：
   * 启动时自动轮询本地 NVIDIA GPU，获取其名称、显存大小、CUDA 支持版本并展示在系统设置与状态栏。
   * 训练过程中，必须限制最大显存占用以防止 OOM（显存溢出）导致的主进程崩溃。
3. **主进程高可用（零闪退）**：
   * Python 计算后端必须作为一个**独立进程**被平台宿主进程管理。
   * 无论 Python 发生何种异常中断、内存溢出（OOM）、显卡驱动超时（TDR），前端必须保持响应，优雅弹窗报错，绝不允许前端闪退。
