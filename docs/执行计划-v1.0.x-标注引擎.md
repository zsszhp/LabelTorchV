# 标炬 LabelTorch 执行计划：v1.0.x 标注引擎正式版

> 版本：1.0
> 状态：待执行
> 前置基线：v0.3.x 产线硬化完成后
> 执行环境：CPU/GPU 皆可，GPU 机更佳（辅助标注与 OBB 训练验证需要）
> 预估周期：4~6 周

---

## 一、目标与非目标

### 1.1 目标

标注能力达到可替代 labelme / x-anything 的实用水平，OBB 链路端到端贯通：

1. 多边形标注可绘制、可编辑、可撤销、可与 YOLO 格式双向闭环，训练可用。
2. 画布体验满足产线连续帧标注节奏：平滑缩放、右键菜单、复制上帧、大图不卡。
3. OBB 从标注 → 数据划分 → 训练 → 导出验证全链路无断点。
4. 辅助标注批量审核产品化，接通已有 `commitConfirmedLabels` / `retrainFromBatch`。
5. 快捷键可配置、标注统计可见，单帧标注效率可量化。

### 1.2 非目标

- 不做增量训练、主动学习队列、错误分析报告（归 v1.1.x）。
- 不做工业元数据、批次追溯、IATF 交付（归 v2.0.x）。
- 不做分割掩码（mask）标注与 SAM 自动分割接入。
- 不做多人协同标注与服务端标注。
- 不更换绘图内核（继续基于 `AnnotCanvasItem` + QPainter）。
- 不做视频抽帧标注工具链（`VideoInferencePage` 仅保持现状可用）。

## 二、任务分解

### A1 多边形标注完善（顶点编辑 / 撤销 / YOLO 格式闭环）

- **涉及文件**：
  - `src/features/annotation/canvas/AnnotCanvasItem.h/cpp`（已有 `m_polygonPoints` 绘制流、`drawDrawingPolygon`、`m_undoStack` 撤销栈 L1154-1181）
  - `src/features/annotation/AnnotationModel.h/cpp`（已有 `addPolygonAnnotation` / `updatePolygonPoint`，PointsRole）
  - `src/features/annotation/AnnotationService.cpp`（`loadPolygonAnnotations` L633 / `savePolygonAnnotations` L690）
  - `src/features/annotation/labelio/YoloTxtReader.cpp` / `YoloTxtWriter.cpp`（`readPolygon` / `writePolygon`）
  - `src/features/annotation/geometry/Polygon.h`
  - `tests/test_labelio.cpp`、`tests/test_geometry.cpp`
- **实现要点**：
  1. 顶点编辑态：选中多边形后高亮顶点，支持拖拽顶点（走 `updatePolygonPoint`）、双击边插入顶点、Del 删顶点（顶点数 < 3 时整体删除并提示）；顶点拖拽与框选拖拽区分命中半径（按当前缩放反比）。
  2. 撤销闭环：顶点增删改全部入 `m_undoStack`，复用现有 `UndoEntry` 快照机制（L1111-1126），确保 Ctrl+Z/Y 与绘制/删除行为一致；绘制中右键取消当前多边形不入栈。
  3. YOLO 格式闭环：归一化坐标 5 位小数写出、原子写入沿用 `writePolygon`；读入时自愈非法点数（<3 丢弃并记 `validation_status`）；HBB/OBB/Polygon 三种 `shapeType`（0/1/2）混存同数据集时互不干扰。
  4. 自闭合与吸附：靠近首点自动闭合（现 `m_nearStartPoint` 已有基础）；顶点移动时对网格/边缘吸附可开关。
- **验收标准**：多边形绘制→顶点编辑→撤销重做→保存→重开项目标签一致；`test_labelio` 新增多边形顶点级读写用例通过；导出 txt 与 labelme 互转抽检 20 条无坐标漂移。
- **预估工作量**：5 人日

### A2 画布体验（平滑缩放 / 右键菜单 / 复制上帧 / 大图虚拟化）

- **涉及文件**：
  - `src/features/annotation/canvas/CanvasController.h/cpp`（缩放/平移/坐标变换/绘制模式）
  - `src/features/annotation/canvas/AnnotCanvasItem.h/cpp`（鼠标事件 L547-980 区域）
  - `src/features/annotation/qml/AnnotationPage.qml`（工具栏 L240-255、快捷键提示 L1504）
  - `src/components/qml/ContextMenu.qml`（组件已有，未接入画布）
  - `src/core/cache/ImageDecodeCache`
- **实现要点**：
  1. 平滑缩放：滚轮缩放以光标为锚点做动画插值（100~150ms），触控板捏合事件映射到同一入口；缩放档位 1%~1600% 连续可变，双击适配窗口。
  2. 右键菜单：复用 `ContextMenu.qml`，条目为「复制框 / 删除 / 改类别（子菜单）/ 锁定 / 全选同类 / 适应窗口」；绘制模式下右键语义保持「结束/取消绘制」，不弹菜单。
  3. 复制上一帧：快捷键（默认 `W`）把上一张样本的全部标注按相同类别拷入当前帧并入撤销栈；图像尺寸不一致时按比例映射并提示；产线连续帧场景下提供「自动带出上帧标注」开关（默认关）。
  4. 大图虚拟化：4K 及以上图片按视口裁剪解码/绘制，`AnnotCanvasItem::paint` 只画可见区域（结合 `ImageDecodeCache` 分块）；空闲时预取相邻帧缩略与全图；目标：万张 4K 浏览 RSS < 1GB（衔接 v0.3 G5 基线）、标注切换 < 500ms、缩放帧率 ≥ 30fps。
- **验收标准**：缩放无跳变、右键菜单全条目可用、复制上帧单帧标注 < 3 秒（10 个框场景）；8K 图纸导入可平移缩放不假死；性能指标达标并记录于基线文档。
- **预估工作量**：6 人日

### A3 OBB 标注 → 训练 → 导出全链路

- **涉及文件**：
  - `src/features/annotation/geometry/RotatedBox`、`AnnotationService`（OBB 读写已具备）
  - `src/features/training/SnapshotService.cpp`（train/val 划分与物理目录准备）
  - `src/features/training/TrainingService.cpp`、`backend/labeltorch_backend/handlers/training.py`
  - `backend/labeltorch_backend/adapters/ultralytics_adapter.py`（yolov8_obb）
  - `backend/labeltorch_backend/tools/data_split.py`
  - `src/features/export/ExportService.cpp`、`backend/labeltorch_backend/handlers/export.py`
  - `tests/test_classify.cpp`（对照新增 `tests/test_obb_e2e.cpp`）
- **实现要点**：
  1. 链路核查：OBB 标签（cls cx cy w h angle 或 ultralytics 四点格式，以 `YoloTxtReader` 现状为准）经 `data_split` 划分后不丢角度信息；`SnapshotService` 对 obb 任务写 `data.yaml` 指向正确标签目录。
  2. 训练接通：`ultralytics_adapter` 对 `task_type=obb` 选择 `yolov8n_obb` 系配置，进度事件、失败诊断（`failure_info_json`）与 detect 同构。
  3. 导出验证：onnx 导出后 `artifact.verify` 对 OBB 输出头做形状断言（N×(4+1+angle+cls) 或实际结构）；导出报告标注任务类型。
  4. UI：标注页 OBB 手柄（旋转柄 + 边柄）完善角度微调；训练页任务类型为 obb 时配置面板过滤不适用项。
- **验收标准**：OBB 样本标注→快照→训练→onnx 导出验证一条命令链路走通；旋转框 mAP 曲线入 `run_metrics`；新测试 `test_obb_e2e.cpp` + 后端 pytest 用例通过；导出模型 ONNX Runtime 推理抽检角度输出合理。
- **预估工作量**：5 人日

### A4 辅助标注批量审核 UI（接 commitConfirmedLabels / retrainFromBatch）

- **涉及文件**：
  - `src/features/inference/AssistedLabelService.h/cpp`（`commitConfirmedLabels` L500、`retrainFromBatch` L670，批量接口已完备：`confirmAllAboveThreshold` / `rejectAllBelowThreshold` / `getHardCaseQueue` 等）
  - `src/features/inference/qml/AssistedLabelPanel.qml`、`ReviewDialog.qml`、`AssistPage.qml`
  - `src/features/inference/qml/LowConfQueue.qml`、`HardCaseQueue.qml`
  - `tests/test_p1_workflow.cpp`（已有 commit/retrain 单测 L234-318）
- **实现要点**：
  1. 批量审核视图：网格 + 键盘流（`A` 确认 / `S` 跳过 / `D` 拒绝 / 方向键切帧），支持全选、按类过滤、置信度滑条过滤；顶部统计条（待审/已确认/已拒绝）走 `getBatchStats`。
  2. 批量动作条：「全部确认 ≥ 阈值」「全部拒绝 < 阈值」「一键提交（`commitConfirmedLabels`）」「提交并发起再训练（`retrainFromBatch`，参数：采样比例/策略/附加配置）」；危险动作二次确认（`ConfirmDialog`），列明将写入的标签数量。
  3. 性能：100 样本批量确认无卡顿（候选列表懒加载、缩略图走 `ThumbnailProvider`）；提交过程显示进度，失败Toast含原因。
  4. 改类：审核时可改候选类别，写回 candidate 后再提交（对应 `edited` 计数）。
- **验收标准**：从生成批次到批量确认→提交→标签落库→再训练请求发出全程 UI 完成；100 样本批量操作响应 < 2 秒；`test_p1_workflow` 回归通过并新增批量阈值确认用例。
- **预估工作量**：4.5 人日

## 四、验收标准与测试用例清单

### 4.1 整版验收标准

1. 多边形可绘制/顶点编辑/导出/训练，重开项目无丢失。
2. OBB 从标注到 onnx 导出验证全通，指标可查。
3. 辅助标注一次批量确认 100 样本无卡顿，提交后标签落库可审计。
4. 连续帧复制后单帧标注 < 3 秒；标注切换 < 500ms；缩放 ≥ 30fps。
5. ctest / pytest 100% 通过，编译 0 错误 0 警告。

### 4.2 测试用例清单

**多边形（C++：`test_labelio` / `test_geometry` 扩展）**
1. 绘制 3/4/20 点多边形保存后读回坐标误差 < 1e-4。
2. 插入/拖拽/删除顶点各 5 次，撤销重做恢复到任意步。
3. 点数 < 3 的非法标签读入被丢弃且 `error_code` 落库。
4. 原子写入中断（模拟）后旧标签完好（回归 `test_labelio_atomic`）。
5. HBB/OBB/Polygon 同数据集互不污染。

**画布（手工 + 自动化混合）**
6. 滚轮以光标为锚缩放，锚点像素不漂移。
7. 右键菜单六条目功能正确；绘制中右键取消。
8. 复制上帧：同尺寸/异尺寸/空上帧三场景。
9. 8K 图平移缩放 30 秒无崩溃，RSS 增幅 < 200MB。

**OBB（`test_obb_e2e` + 后端 pytest）**
10. OBB 标签划分后 train/val 数量与角度信息一致。
11. yolov8n_obb 训练 3 epoch 产出 metrics 与 best 权重。
12. onnx 导出 + `artifact.verify` 形状断言通过。

**辅助标注（`test_p1_workflow` 扩展）**
13. `confirmAllAboveThreshold` + `commitConfirmedLabels` 落库数量正确。
14. `retrainFromBatch` 触发训练请求且参数快照入库。
15. 100 样本批量确认计时 < 2 秒（测试机记录基线）。

**快捷键与统计**
16. 重绑定→冲突提示→恢复默认→重启生效。
17. 统计数字与抽检 20 样本标签聚合一致。
18. 万张数据集统计查询 < 1 秒。

## 六、风险与依赖

| 风险/依赖 | 影响 | 应对 |
|-----------|------|------|
| 多边形顶点命中与现有框选交互冲突 | 编辑体验差 | 命中优先级明确：顶点 > 边 > 整体 > 背景；缩放反比半径 |

| 辅助标注批量写库量大引发锁 | 卡顿 | 事务批量写 + 进度事件；沿用 WAL |
| 快捷键与全局快捷键（Ctrl+1~8）冲突 | 功能互抢 | 冲突检测白名单 + 提示 |
| 6 周排期依赖 GPU 机到位（A3/A4 验证） | 延期 | A1/A2/A5 可先在 CPU 机完成 |
