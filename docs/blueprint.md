# 标炬（LabelTorch）产品蓝图与版本规划

> 版本：6.0 | 更新日期：2026-09-29
> 状态：当前有效蓝图（对齐 v0.2.0）

---

## 一、产品定位

标炬（LabelTorch）是面向工业缺陷检测场景的本地离线桌面平台，把数据导入、数据治理、训练、测试、智能辅助与导出交付收敛到一个统一工作台中。

当前产品路线遵循两条核心原则：

1. 先保证训练闭环稳定可用
2. 再逐步建设高保真工业级 UI 和完整标注生态

---

## 二、当前阶段总目标

当前阶段采用 `MVP+` 路线，目标由两部分组成。

### 2.1 业务闭环目标

必须优先打通并稳定以下链路：

1. 项目创建与打开
2. 数据集导入（YOLO txt / COCO json / 图片无标签）
3. 数据集扫描与异常提示（重复图、跨划分泄漏、坏标签）
4. 数据冻结版生成（哈希冻结，训练前校验）
5. 训练参数配置
6. `YOLOv8` 目标检测训练（含 OBB / 分类 / 异常检测）
7. 模型测试评估（PR 曲线、混淆矩阵、逐类指标、阈值推荐）
8. `pt` / `onnx` 导出
9. 导出后验证（ONNX Runtime / TorchScript 校验）
10. 交付目录生成（模型 + classes.yaml + thresholds.json + warmup.py）

### 2.2 UI 目标

UI 采用高保真工业风路线，参考源为：

- `reference/Dihuge DLTools/gemini-code-1780391652706.html`

该参考源决定页面布局、视觉语言、组件层级、按钮风格、状态反馈和主要弹窗结构。

## 三、系统功能版图

平台当前按 **8 个主页面** 组织，分为三组：

| 分组 | 页面 | pageId | 承载 |
|------|------|--------|------|
| **数据（4）** | 项目 | `project` | 项目创建/打开、任务类型、最近项目 |
| | 数据集 | `dataset` | 导入向导入口、样本浏览、统计、Tag 管理 |
| | 检查 | `check` | 数据质量核查、异常样本定位、重复/泄漏检出 |
| | 标注 | `annotation` | HBB/OBB/分类标注、修订追踪、辅助标注审核 |
| **训练评估（2）** | 训练 | `training` | 数据冻结版选择、参数配置、训练监控、失败诊断 |
| | 测试 | `test` | 模型评估、PR 曲线、混淆矩阵、阈值推荐、Go/No-Go |
| **交付（2）** | 智能辅助 | `assist` | 辅助标注、难例挖掘、异常检测、视频推理 |
| | 导出 | `export` | pt/onnx 导出、产物验证、交付目录、模型中心入口 |

整体框架采用：

1. 左侧可折叠导航栏（按任务类型裁剪可见项）
2. 主内容区（StackLayout + Loader 按需加载）
3. 可调分栏面板
4. 底部日志面板（可折叠）与状态栏

### 3.1 孤页入口（不占导航，由宿主页面跳转）

孤页共 6 个，进入后标题栏显示「返回」面包屑：

| 孤页 | pageId | 宿主 | 进入方式 |
|------|--------|------|----------|
| 数据导入向导 | `import` | 数据集 | DatasetPage「导入向导」按钮 |
| 类别映射 | `classmap` | 数据集 | 导入流程第 2 步 |
| 类别体系 | `taxonomy` | 项目 | 项目页「类别管理」 |
| 数据冻结版 | `snapshot` | 训练 | 训练页「数据冻结版」子区 |
| 模型中心 | `model` | 导出 | 导出页「模型版本」侧栏 |
| 指标对比 | `compare` | 导出 | 测试页 / 模型中心「对比」 |

### 3.2 项目

负责项目创建、打开、最近项目访问、任务类型切换（detect/obb/classify/anomaly）和项目级默认配置。

### 3.3 数据集

负责导入、扫描、样本浏览、样本属性、Tag 管理和划分准备。导入支持 YOLO txt、COCO json、图片无标签三种形态。

### 3.4 检查

负责问题样本浏览、重复图检出、train/val 跨划分泄漏检测、坏标签定位和质检流程承载。

### 3.5 标注

承载 HBB、OBB、分类标注与修订追踪（undo/audit），并作为辅助标注结果的人工审核入口。

### 3.6 训练

1. 数据冻结版（快照）选择与创建
2. 网络结构与模型家族选择
3. 训练参数配置（含配置模板）
4. 数据增强配置
5. 训练状态与实时指标展示
6. 训练失败诊断（日志尾部 + 一键降 batch/imgsz 建议）

### 3.7 测试

模型评估视图：PR 曲线、混淆矩阵、逐类 AP/P/R、部署阈值推荐、万件漏检/超检预估、产线 KPI Go/No-Go。

### 3.8 智能辅助

合并原推理 / 主动学习 / 辅助标注入口：

1. 辅助标注：推理候选框审核、批量确认/拒绝、回写 YOLO txt
2. 难例挖掘：低置信 / 误检 / 漏检 / 难例队列（落库重启不丢）
3. 异常检测：单图/批量异常热力图推理
4. 视频推理：视频抽帧推理（性能底线，不做实时流）

### 3.9 导出

承载真实的导出与验证能力，是核心闭环一部分。内嵌模型中心（模型版本、血缘、标签）与交付目录生成。

## 四、当前阶段范围边界

6. 导航收敛为 8 页 + 6 孤页，无不可达页面
7. 关键不可逆操作全部入审计（task_events）

1. OBB 完整训练闭环
2. 分类完整训练闭环
3. 完整标注引擎交付
4. 辅助标注正式版
5. 增量训练完整产品化
6. TensorRT、TFLite、Engine 等完整导出闭环
7. Ubuntu 交付级兼容
8. 匹配页面

## 五、版本路线图

### v0.1.x：MVP+ 稳定化阶段

交付重点：

1. 项目、数据集、训练、导出主链路稳定
2. `YOLOv8 detect + anomaly` 可用
3. `pt + onnx` 导出与验证可用
4. 高保真 UI 骨架完成

### v0.2.x：稳定性收口与体验闭环（当前）

交付重点：

1. P0 稳定性与数据安全收口（快照哈希冻结、级联删除、原子写入、崩溃捕获）
2. P1 导航收敛 8 页、UX 反馈体系（Toast/空态/确认框）、主工作流闭环
3. P2 交付与治理（审计落地、用户手册、版本对齐、E2E 门禁）
4. 导出交付目录、训练失败诊断、难例挖掘队列落库

### v1.0.x：标注引擎阶段

交付重点：

1. HBB 标注
2. OBB 标注
3. 多边形标注
4. 撤销重做与原子写回

### v1.1.x：辅助标注与增量训练阶段

交付重点：

1. 历史模型辅助标注
2. 批量审核
3. 增量训练入口
4. 模型血缘链增强

### v2.x：数据治理与全生命周期阶段

交付重点：

1. 快照体系强化
2. 主动学习
3. 模型版本治理
4. 多模型家族扩展

## 六、关键设计边界

1. Qt/C++ 主进程负责 UI、本地状态、数据库和 Python 子进程管理
2. Python 后端负责训练、导出、验证、推理等计算任务
3. 训练必须基于不可变数据冻结版（快照，manifest 记内容哈希）
4. 模型版本必须可追溯到训练运行和数据冻结版
5. 导出产物必须经过验证
6. 不可逆操作必须可审计（`annotation_revisions` / `task_events`）
7. 软件必须支持离线使用和 CPU 降级路径

## 八、执行原则

1. 先稳定闭环，再扩展页面功能
2. 先统一组件和设计系统，再复刻页面
3. 先复刻 UI 外壳，再接真实数据
4. 每个阶段都按里程碑验收
5. 产品优化执行以 `docs/产品优化实施计划.md` 为总控文档
