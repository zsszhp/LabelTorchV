# 标炬 LabelTorch 执行计划：v0.3.x 产线硬化

> 版本：1.0
> 状态：待执行
> 前置基线：v0.2.0（P0/P1/P2 已完成并推送）
> 执行环境：GPU 开发机（Windows 10/11 x64 + NVIDIA GPU，见 `docs/GPU开发机交接指南.md`）
> 预估周期：2~3 周

---

## 一、目标与非目标

### 1.1 目标

把「开发机上能跑」变成「客户产线工控机上敢用」：

1. GPU 版依赖进入交付包，30/40/50 系显卡实测留档，训练开箱即用。
2. IFW 安装器实包可安装/升级/卸载，卸载与升级不丢用户项目数据。
3. 万张 4K 真实数据全链路压测通过，产出可对比的性能基线表。
4. 空态、表单校验、日志级别设置等体验缺口全部收尾，无裸文字提示。
5. 崩溃/断电场景下数据可恢复，稳定性回归全绿。

### 1.2 非目标

- 不做标注引擎升级（多边形顶点编辑、OBB 全链路等归 v1.0.x）。
- 不做增量训练、主动学习闭环、错误分析（归 v1.1.x）。
- 不做工业元数据、IATF 报告、数据血缘（归 v2.0.x）。
- 不引入云端服务、账号体系、在线许可证校验。
- 不做代码签名采购决策（无证书则在交付说明中明示）。

## 三、任务分解

### G1 GPU 版 torch 打包（cu121 / cu124）

- **涉及文件**：`scripts/build_green_package.ps1`（现有 `-IncludeAnomaly`、`-PythonMode trim` 白名单约 L324-380）、`backend/requirements.txt`、`docs/用户手册/`（交付说明）、`CHANGELOG.md`
- **实现要点**：
  1. 新增 `-IncludeCuda` 开关与 `-CudaVersion cu121|cu124` 参数；开启时用 `pip install torch torchvision --index-url https://download.pytorch.org/whl/{cu121|cu124}` 覆盖 CPU 版后再 trim，白名单必须保留 `torch/lib/*cudart*`、`*cublas*`、`*cudnn*`、`*nvrtc*` 等 CUDA 动态库（当前 trim 按包名白名单保留整个 `torch/` 目录，需回归确认 DLL 未被误删）。
  2. 体积控制：CUDA 包约 3~5 GB，`-SkipZip` 默认对 CUDA 包开启或改用 7z 分卷；README 草稿（打包脚本内生成的说明文件，约 L442 附近）同步改为「本包内嵌 GPU 版 PyTorch」。
  3. 冒烟扩展：`-SkipSmoke` 对应的校验清单增加 `import torch; torch.cuda.is_available()` 与一次 `model.train(epochs=1)` 的 GPU 检查断言。
- **验收标准**：在 GPU 机打出 cu121 与 cu124 两个绿色包；解压后 `environment.check` 返回 `gpu_name` 非空、`gpu_memory_total_mb` 正确；一轮 1 epoch 训练实际占用 GPU（`nvidia-smic` 可见进程）；CPU 机解压 cu 包时程序可启动且训练走 CPU 降级不崩溃。
- **预估工作量**：3 人日

### G2 30/40/50 系显卡测试矩阵与记录模板

- **涉及文件**：`docs/测试记录-GPU矩阵.md`（新建）、`docs/GPU开发机交接指南.md`（补记录路径）
- **实现要点**：
  1. 矩阵行：显卡型号（如 RTX 3060 / 4060 / 5060 或实际可得型号）× CUDA 构建（cu121/cu124）× 任务类型（detect / obb / classify / anomaly）。
  2. 记录模板列：日期、驱动版本、`nvidia-smi` 截图存档名、包版本（`sync_version.ps1 -CheckOnly` 输出）、训练配置（imgsz/batch/epochs）、峰值显存、单 epoch 耗时、导出格式与验证结果、结论（通过/失败/限制说明）。
  3. 失败项必须附日志尾部与 `training_runs.failure_info_json` 摘要。
- **验收标准**：至少 3 张不同代际显卡完成「导入 → 训练 50 epoch → 测试 → 导出 onnx + 验证」全链路记录；矩阵表无空行；50 系若驱动/算力不兼容，记录明确的阻塞原因与回退方案。
- **预估工作量**：2 人日（不含排队等机）

### G3 GPU 显存预检与 batch 自动建议

- **涉及文件**：`backend/labeltorch_backend/handlers/environment.py`（已有 `gpu_memory_total_mb`）、`backend/labeltorch_backend/handlers/training.py`、`src/features/training/qml/ConfigPanel.qml`、`src/features/training/TrainingService.cpp`
- **实现要点**：
  1. 后端新增 `train.suggest_batch`（或扩展 `environment.check`）：按显存总量、模型规模（n/s/m/l）、imgsz 估算安全 batch，返回建议值与保守值；算法写在 `backend/adapters/ultralytics_adapter.py`，参数可配置。
  2. 训练启动前预检：`train.start` 内检查可用显存，不足时返回结构化错误（缺多少 MB、建议 batch/imgsz），由 `TrainingService` 弹 Toast 而非静默失败。
  3. `ConfigPanel.qml` 显示「建议 batch」按钮，点击回填；手动值超出上限时黄色警告不阻断。
- **验收标准**：在 8GB / 12GB / 16GB 显存机器上建议值误差不超过一档；显存不足场景训练被拦下且提示含解决方案；单测覆盖估算函数的边界（4GB 以下、48GB 以上）。
- **预估工作量**：2.5 人日

### G4 IFW binarycreator 实包 + 升级卸载数据保护

- **涉及文件**：`installer/config/config.xml`、`installer/config/control.js`、`installer/packages/com.labeltorch.main/meta/installscript.qs`、`installer/packages/com.labeltorch.main/meta/package.xml`、`scripts/build_installer.ps1`（新建）
- **实现要点**：
  1. 新增 `build_installer.ps1`：调用绿色包产物填入 `packages/com.labeltorch.main/data/`，再用 `binarycreator --offline-only` 生成安装器 exe。
  2. `installscript.qs` 实现：安装不覆盖用户数据目录（项目根、`labeltorch.db` 所在 `AppDataLocation`）；升级前备份数据库文件；卸载时检测非空项目目录，弹确认「保留数据 / 一并删除」，默认保留。
  3. 静默安装/卸载参数（`--silent`）走同一保护逻辑；安装包内写入版本号并由 `sync_version.ps1` 统一。
- **验收标准**：干净虚拟机安装 → 建项目导入数据 → 升级安装 → 项目与数据库完好 → 卸载默认保留数据 → 重装后历史项目可打开；全程无管理员权限硬依赖；安装器体积与绿色包差异可解释。
- **预估工作量**：3 人日

### G5 万张 4K 真实数据压测与性能基线表

- **涉及文件**：`docs/性能基线-v0.3.md`（新建）、`src/core/cache/ThumbnailCache` / `ThumbnailProvider` / `ThumbnailGenerator`、`src/features/dataset/DatasetService.cpp`、`src/features/annotation/qml/AnnotationPage.qml`
- **实现要点**：
  1. 压测数据集：≥10000 张 4K 图 + YOLO 标签，写入固定数据集目录；脚本化准备步骤记入基线文档（不入库）。
  2. 压测项与指标：导入耗时、缩略图首屏、滚动 RSS、标注前后帧切换耗时、训练启动到首个 epoch、导出耗时；用任务管理器 / 自带日志时间戳采样，每项跑 3 次取中位数。
  3. 若滚动 RSS ≥ 1GB 或切换 ≥ 500ms，优先排查 `ThumbnailCache` 字节上限、`ImageDecodeCache` 失配、`GridView` 单帧全量加载，修到红线内再出基线表。
- **验收标准**：滚动浏览 RSS < 1GB；标注切换 < 500ms；万张导入在可接受时长内完成并有进度提示不假死；基线表含硬件配置列，可复测对比。
- **预估工作量**：3 人日（含调优缓冲）

  3. 不改变现有布局尺寸体系，颜色/字号全部走 `Theme`。
- **验收标准**：走查三页全部空态分支截图留档，无纯文字裸提示；按钮可点击且路由正确；qmllint 无新增告警。
- **预估工作量**：2 人日
