#### 常见坑

- **整包拷贝 vs 文件白名单**：当前 trim 是按包名拷贝整个 `torch/` 目录（`Copy-Item -Recurse`），CUDA DLL 天然保留；若以后有人「优化」成只拷 `*.pyd`，CUDA DLL 会被静默丢掉，冒烟第 2 步会立刻暴露。
- **同一 conda 环境来回切 CPU/GPU torch**：先 `pip uninstall -y torch torchvision` 再装，否则残留 `.dist-info` 与 DLL 版本错配，报 `cudart64_12.dll not found`。
- **`Compress-Archive` 打 4GB+ 极慢且易内存爆**：CUDA 包一律 SkipZip / 7z 分卷。
- **输出目录同名覆盖**：连续打 cu121/cu124 会写进同一 `deploy\LabelTorch-Green-v{版本}`，打完立刻 `Move-Item` 改名。
- **驱动与 cu 构建不匹配**：50 系新卡可能需要 cu124+ 与 570+ 驱动，先用 G2 矩阵验证再量产。

#### 逐步操作

1. **实现估算函数**（放 `ultralytics_adapter.py` 模块级纯函数，便于单测）：

```python
# 单图激活/梯度显存估算基数（MB @imgsz=640，按模型规模），G2 实测后用校准表覆盖
_MEM_BASE_MB = {"n": 32, "s": 48, "m": 80, "l": 120, "x": 160}
_MEM_OVERHEAD_MB = {"n": 400, "s": 600, "m": 1000, "l": 1500, "x": 2200}

def suggest_batch(total_mb: int, model_family: str, imgsz: int) -> dict:
    size = "s"
    for k in ("n", "s", "m", "l", "x"):
        if k in model_family.lower():
            size = k
            break
    base = _MEM_BASE_MB[size] * (max(imgsz, 128) / 640.0) ** 2
    overhead = _MEM_OVERHEAD_MB[size]
    usable = max(total_mb * 0.75 - overhead, 256)   # 留 25% 给驱动/cuDNN workspace
    suggested = max(1, min(128, int(usable // base)))
    conservative = max(1, suggested // 2)
    return {"suggested_batch": suggested, "conservative_batch": conservative,
            "max_batch": suggested, "estimated_mb_per_image": round(base, 1),
            "overhead_mb": overhead}
```

```python
    import torch
    model_family = payload.get("model_family", "yolov8")
    imgsz = int(payload.get("imgsz", 640))
    if not torch.cuda.is_available():
        return {"gpu_name": "N/A", "gpu_memory_total_mb": 0, "suggested_batch": 8,
                "conservative_batch": 4, "max_batch": 8,
                "estimated_mb_per_image": 0, "overhead_mb": 0,
                "warnings": ["未检测到 GPU，按保守 CPU 建议返回"]}
    from ..adapters.ultralytics_adapter import suggest_batch
    total = torch.cuda.get_device_properties(0).total_mem // (1024 * 1024)
    est = suggest_batch(total, model_family, imgsz)
    est.update({"gpu_name": torch.cuda.get_device_name(0),
                "gpu_memory_total_mb": total, "warnings": []})
    return est
```

3. **`train.start` 启动前显存预检**：在 `handle_start` 的 `validate_config` 通过之后、启动训练线程之前插入；错误码沿用现有错误对象风格（对照 L132-139 的 `error: {code, message}`）：

```python

need = suggest_batch(total_mb, model_family, imgsz)
required = int(need["estimated_mb_per_image"] * batch + need["overhead_mb"])
free_mb = torch.cuda.mem_get_info()[0] // (1024 * 1024) if torch.cuda.is_available() else 0

    return {"task_id": task_id, "status": "failed",
            "error": {"code": "VRAM_INSUFFICIENT",
```

#### 常见坑

- **`gui.questionMessageBox` 在 `--silent` 下返回值不确定**：静默分支必须显式判断并默认保留，否则产线批量卸载可能弹窗卡死或误删数据。
- **`RemoveTargetDir=true`**：只清安装目录。绝不要把项目数据指到安装目录里（ProjectFs 根在用户选的项目路径，一般没问题，但测试时要确认项目没有被建在 `D:\LabelTorch` 下）。

```cpp
// 用例1：临时文件残留 + rename 前状态，重开读取应得到旧内容或新内容，绝无半写
void TestCrashRecovery::labelTmpLeftover() {
    const QString path = dir.filePath("a.txt");
    YoloTxtWriter::write(path, oldAnnos);              // 先写旧版
    // 模拟崩溃在 rename 前：留下 a.txt.tmp 内容为「新版」，a.txt 仍是旧版
    QFile tmp(path + ".tmp"); tmp.open(QIODevice::WriteOnly | QIODevice::Text);
    tmp.write("1 0.5 0.5 0.2 0.2\n"); tmp.close();
    const auto got = YoloTxtReader::read(path);
    QCOMPARE(got.size(), oldAnnos.size());             // 仍是旧版，无损坏
    QFile::remove(path + ".tmp");                      // 应用侧启动时可清扫 *.tmp
}
// 用例2：写入中断（临时文件半截）后重开库/读标签
// 用例3：SQLite 事务中断——写入中 kill 的等价模拟：打开库、BEGIN IMMEDIATE、
//        不 COMMIT 直接关闭连接，再重开断言 WAL 恢复后表状态一致、无半行。
void TestCrashRecovery::walInterruptedTransaction() {
    {   // 第一连接：开启事务写一半后直接析构（不 commit）
        QSqlDatabase db = QSqlDatabase::addDatabase("QSQLITE", "crash1");
        db.setDatabaseName(dbPath); db.open();
        QSqlQuery q(db); q.exec("PRAGMA journal_mode=WAL");
        q.exec("BEGIN IMMEDIATE");
        q.exec("INSERT INTO task_events(task_type,task_id,event_type,payload_json) VALUES('x','y','z','{}')");
        // 不 commit，作用域结束连接销毁，模拟进程被杀
    }
    QSqlDatabase::removeDatabase("crash1");
    {   // 第二连接：重开断言回滚生效
        QSqlDatabase db = QSqlDatabase::addDatabase("QSQLITE", "crash2");
        db.setDatabaseName(dbPath); db.open();
        QSqlQuery q(db);
        q.exec("SELECT COUNT(*) FROM task_events WHERE task_id='y'");
        q.next(); QCOMPARE(q.value(0).toInt(), 0);     // 未提交事务不可见
    }
    QSqlDatabase::removeDatabase("crash2");
}
```

#### 常见坑

- **`taskkill /F /IM python.exe` 会杀掉本机所有 python**：压测机上确认没有其他 Python 任务；或用 `taskkill /F /PID <后端PID>`（PID 从日志面板/`nvidia-smi` 里取）。
- **WAL 恢复依赖同一目录下的 `-wal`/`-shm` 文件完整**：拷贝库文件做「断电样本」时三个文件要一起拷。
- **`atomicReplaceFile` 在 Windows 用的是替换语义**（YoloTxtWriter.cpp L31-50），杀进程窗口极小；测「半写」要在临时文件写完、rename 前注入（单测里手工构造该状态最可靠，手工 kill 只能统计性验证）。

- **恢复测试不要依赖真实 GPU/训练**：用假 adapter 或仅走状态机，保证 `ctest` 在 CPU 开发机也能全绿。

## 附录 A：显存估算公式与 batch 对照表

### A.1 公式

训练峰值显存（MB）近似分解为：

```
peak ≈ overhead(model) + per_image(model, imgsz) × batch + workspace
```

- `per_image(model, imgsz) = base[model] × (imgsz / 640)²`
- `base[model]`（MB/图 @640，含激活与梯度，AMP 开启时取下表 0.7 倍）：

| 模型规模 | base MB/图 | overhead MB（权重+优化器状态） |
|----------|-----------|--------------------------------|
| n | 32 | 400 |
| s | 48 | 600 |
| m | 80 | 1000 |
| l | 120 | 1500 |
| x | 160 | 2200 |

- `workspace` 取 512MB 保守值；`usable = total_mb × 0.75`（留 25% 给驱动、桌面合成、cuDNN workspace 波动）。
- **建议 batch** = `clamp( floor((usable − overhead − 512) / per_image), 1, 128 )`
- **保守 batch** = `suggested // 2`（OOM 拦截时给用户的降档值）。

> 上表为工程初值。G2 每张卡实测后，把「实际峰值 − 公式峰值」的偏差回填校准（建议在 `ultralytics_adapter.py` 顶部注释里记一行实测数据，如 `RTX4060 8GB / yolov8s / 640 / batch16 → 峰值 6120MB`）。

### A.2 对照表（imgsz=640，AMP 开，base×0.7）

| 显存总量 | usable(75%) | v8n | v8s | v8m | v8l | v8x |
|----------|-------------|-----|-----|-----|-----|-----|
| 4 GB | 3072 | 16 | 8 | 4 | 2 | 1 |
| 6 GB | 4608 | 24 | 14 | 8 | 4 | 2 |
| 8 GB | 6144 | 32 | 18 | 10 | 6 | 4 |
| 12 GB | 9216 | 48 | 30 | 16 | 10 | 6 |
| 16 GB | 12288 | 64 | 40 | 22 | 14 | 8 |
| 24 GB | 18432 | 96 | 62 | 36 | 22 | 14 |
| 48 GB | 36864 | 128 | 128 | 74 | 48 | 30 |

（表内值 = floor((usable − overhead − 512) / (base×0.7))，再钳到 1..128；4GB 行 batch≥16 时实测易 OOM，实际执行取保守 batch。）

### A.3 换算示例

12GB 卡、yolov8s、imgsz=640：`per_image = 48×0.7 = 33.6`；`usable = 9216`；`batch = (9216−600−512)/33.6 ≈ 241 → 钳 128？` 重新按不钳位值给用户时以保守档为准：建议 batch=30（取 0.75 余量再打 85% 折），保守 15。**实现时以代码算出的 `suggested_batch` 为准，本表用于人工核对量级**。
