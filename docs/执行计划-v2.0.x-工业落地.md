## 1. 目标与非目标

### 1.1 目标

满足电池 / 3C / 金属表面缺陷产线的追溯与交付要求，让「模型交付给集成商」成为可审计、可追溯、可复现的标准动作：

1. **工业元数据**：样本级批次 / 料号 / 工位 / 相机 / 条码 / 缺陷等级落库，支持 CSV 旁路导入，按批次筛选与追溯。
2. **数据治理视图**：样本→快照→训练→模型→导出全链路血缘图、质量趋势时序、去重 / 合并 / 批量修标签工具。
3. **产线交付包**：IATF 风格审计报告、模型-产线映射（deploy_target）、完整部署目录一键产出。
4. **可选项**：项目打包同步、只读审计导出（资源允许时做，见任务 H）。

### 1.2 非目标（本期明确不做）

1. MES / SPC / PLC 系统实时对接（只做文件级旁路导入与导出，不做在线协议）。
2. 多机协同编辑、权限系统、账号体系。
3. 新算法能力（分割、分类新模型等）。
4. 云端部署与远程推理服务。
5. 条码枪硬件驱动集成（只解析条码字符串字段）。

## 2. 与 v1.1 的依赖关系

| 依赖点 | 来自 v1.1 | 本计划中的用法 | 未就绪时的处置 |
|--------|-----------|----------------|----------------|
| 增量训练血缘 | A1 落库的 `model_version_id` 父子链与 `config_snapshot_json` | 血缘图「训练→模型」边直接取自该链 | 血缘图降级为快照→模型弱链，并在图上标注「血缘不完整」 |
| 版本治理记录 | D1/D2 晋级 / 回滚审计 | IATF 报告的「变更与批准记录」章节 | 报告该章节留空并注明无治理记录 |
| 错误分析报告 | C3 自包含 HTML 报告骨架 | IATF 精度报告章节复用其图表与失败案例组件 | 审计报告只出结论表，不出失败案例 |

## 4. 数据库迁移方案（Schema V5）

迁移版本 V4 → V5，由 `Database` 迁移管理器在启动时顺序执行，全程事务化；失败自动回滚并保留旧库可用。

```sql
-- V5-1 样本工业元数据（全部可空，兼容旧数据）
ALTER TABLE dataset_samples ADD COLUMN lot_no TEXT;
ALTER TABLE dataset_samples ADD COLUMN part_no TEXT;
ALTER TABLE dataset_samples ADD COLUMN station TEXT;
ALTER TABLE dataset_samples ADD COLUMN camera TEXT;
ALTER TABLE dataset_samples ADD COLUMN barcode TEXT;
ALTER TABLE dataset_samples ADD COLUMN defect_grade TEXT;

-- V5-2 追溯与筛选索引
CREATE INDEX IF NOT EXISTS idx_samples_lot ON dataset_samples(dataset_id, lot_no);
CREATE INDEX IF NOT EXISTS idx_samples_barcode ON dataset_samples(dataset_id, barcode);
CREATE INDEX IF NOT EXISTS idx_samples_grade ON dataset_samples(dataset_id, defect_grade);

-- V5-3 产线部署映射
CREATE TABLE IF NOT EXISTS deploy_targets (
  id TEXT PRIMARY KEY,
  project_id TEXT NOT NULL REFERENCES projects(id),
  line_name TEXT NOT NULL,
  station TEXT,
  camera TEXT,
  model_version_id TEXT NOT NULL REFERENCES model_versions(id),
  effective_at DATETIME DEFAULT CURRENT_TIMESTAMP,
  note TEXT,
  created_by TEXT,
  status TEXT NOT NULL DEFAULT 'active'
);
CREATE INDEX IF NOT EXISTS idx_deploy_targets_proj ON deploy_targets(project_id, status);
```

迁移约束：

1. 迁移前自动备份 `labeltorch.db` 至 `labeltorch.db.v4.bak`（原子复制）。
2. 迁移后自检：样本数、快照数、模型版本数与迁移前一致，不一致即拒绝切换。
3. `Schema.h` 表名常量同步补 `DEPLOY_TARGETS`；测试 `test_database` 补 V5 迁移用例（含空库升级、旧库升级、重复迁移幂等）。
4. 降级不支持：V5 库不允许被旧版本程序打开，启动时版本检查明确报错。

## 6. 验收标准

1. **追溯闭环**：按批次可追溯到训练数据与模型版本，给定导出产物能回溯到样本集合，断链可见。
2. **元数据完整**：六个工业字段可导入、可筛选、可统计；旧库升级无损。
3. **交付就绪**：导出交付包（含 IATF 报告、校验清单、deploy_target.json）解压后按 README 在干净虚拟机跑通推理样例，可直接交给集成商。
4. **审计合规**：审计报告符合客户质量体系清单核对；治理类操作全部有 `task_events` / `annotation_revisions` 留痕。
5. **质量门禁**：编译 0 错 0 警、ctest / pytest 全绿、ruff / qmllint 无新增问题、版本同步脚本通过、绿色包冒烟通过、CHANGELOG 与用户手册同步。
