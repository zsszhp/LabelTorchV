# 05 故障排查

本章汇总常见问题与处理方法。仍无法解决时，请附上日志（底部日志面板或项目目录 `logs/`）反馈。

## 一、启动与连接

### 1. 双击启动脚本后无反应

| 检查项 | 处理 |
|--------|------|
| 路径含中文/空格/特殊符号 | 把绿色包移到纯英文路径，如 `D:\LabelTorch\` |
| 是否通过 `start_LabelTorchV.bat` 启动 | 推荐用启动脚本，它会配好内嵌 Python 搜索路径 |
| 缺少运行库 | 确认绿色包完整解压，DLL 未被杀软隔离 |

### 2. 状态栏显示 Python 后端未连接

1. 点击状态栏「**重连**」按钮
2. 检查「设置」里的 Python 路径是否正确（绿色包默认内嵌 `python\python.exe`）
3. 查看日志面板是否有 `lt.ipc` 相关报错
4. 若使用外部 Python，确认已安装 `ultralytics` 等依赖

> 后端进程崩溃会自动重启（最多 5 次，指数退避）。反复失败时请查日志。

### 3. 修改 Python 路径后不生效

指定外部 Python 路径后需**重启后端**（重连或重启应用）。

## 二、数据导入

### 1. 导入后样本数为 0

- 确认图片目录确实包含支持的图片格式
- YOLO txt 模式下，标签文件名需与图片同名（如 `a.jpg` ↔ `a.txt`）
- 标签格式应为 `class_id cx cy w h`（归一化 0~1）

### 2. 大量「标签无效」

标签格式错误（类别 ID 越界、坐标越界、字段数不对）会被标记为无效。进入「**检查**」页面筛选 `标签无效` 样本逐一修正。

### 3. 类别顺序不一致

源标签的类别顺序与项目类别体系不同时，在导入流程第 2 步「**类别映射**」建立映射规则，不要手工改标签文件。

### 4. 检查页报「重复图 / 跨划分泄漏」

- 重复图：同一图片内容被导入多次，按需删除重复样本
- 跨划分泄漏：同一 hash 同时出现在 train 和 val，会导致评估虚高，必须清理

## 三、数据冻结版（快照）

| 错误码 | 含义 | 处理 |
|--------|------|------|
| `E_SNAPSHOT_NOT_FOUND` | 快照不存在 | 重新创建数据冻结版 |
| `E_MANIFEST_INVALID` | 快照清单缺失或格式非法，或缺少内容哈希 | 删除该冻结版后重新创建 |
| `E_SOURCE_DRIFT` | 源数据已变更（哈希不一致） | 训练将使用冻结标签或提示物化冻结副本；如需用新标注请新建冻结版 |
| `E_FILE_MISSING` | 源文件缺失 | 检查数据集图片/标签是否被移动或删除 |
| `E_COPY_FAILED` | 拷贝失败 | 检查磁盘空间与目录读写权限 |
| `E_DB_ERROR` | 数据库错误 | 查看日志面板 `lt.db` 详情 |

## 四、训练

### 1. 启动训练提示「IPC 未连接」

Python 后端未就绪，见本章一.2。点击重连后重新启动训练。

### 2. 训练失败，想看原因

失败的训练运行会写入**失败诊断**（日志尾部 + 结构化建议），在训练页点击该次运行即可查看，并提供「**一键降 batch/imgsz**」建议按钮。

常见原因与建议：

| 现象 | 建议 |
|------|------|
| 显存不足（CUDA out of memory） | batch 减半、imgsz 降至 320；或换更小模型、关闭其他 GPU 进程 |
| 标签读取失败 | 检查标签格式（`class_id cx cy w h`，归一化 0~1）、图片与标签路径对应关系 |
| 模型/类别数不匹配 | 检查模型族与任务类型是否匹配、类别数与类别体系定义是否一致 |
| 其他 | 查看日志尾部定位报错，降低 batch / epochs 后重试 |

### 3. 训练极慢

- 确认使用 GPU：状态栏 GPU 指示是否正常，`device` 配置是否为 `auto`/GPU 编号
- CPU 训练属预期慢路径，仅建议小数据集验证
- 大数据集可先减小 imgsz 或 epochs 验证链路

### 4. 停止训练超时

停止请求 30 秒内未收到后端确认会标记为 failed，属保护机制。如后端进程实际仍在运行，重启后端后检查任务列表。

## 五、测试评估

- **PR 曲线为空**：确认评估数据已选且样本量 > 0
- **指标异常偏高**：检查 train/val 是否存在跨划分泄漏（检查页可检出）
- **Go/No-Go 结论异常**：确认阈值与 KPI 配置符合产线实际要求

## 六、导出

| 现象 | 处理 |
|------|------|
| 导出状态为 `failed` | 查看日志面板；确认权重文件存在、路径未被移动 |
| 验证失败 | 产物状态为 `failed`，**不可**标记生产；重新导出或检查 onnx 配置（opset 等） |
| `pt` 导出免验证 | 按 TorchScript 校验对齐，属预期行为 |
| tflite/engine 无验证 | 会明确标记 `verified:false`，部署前请自行验证 |

## 七、界面显示

### 1. 界面卡顿、缩略图加载慢

- 大数据集建议关闭重开页面触发缓存重建
- 缩略图按内存字节限容，超限会自动淘汰后重算

### 2. 提示「建议保存后重启」

Debug 版在 Qt 6.11 布局引擎存在 NaN 检测告警，累计超阈值会提示。保存工作后重启应用即可，不影响数据。

### 3. 弹窗/按钮无响应

按 `Esc` 尝试关闭弹窗；仍无响应时查看日志面板并重启应用。

## 八、数据安全相关

- **删除项目**会二次确认并列明连带删除项（数据集/样本/冻结版/训练运行/模型/导出产物），删除后不可恢复，磁盘目录一并清理
- **删除数据集**同样会级联清理关联记录
- 关键不可逆操作（删除/导入/训练启停/导出）均写入审计日志，可供追溯

## 九、获取帮助

1. 按 `F1` 打开使用帮助
2. 底部日志面板复制相关错误（`lt.*` 分类）
3. 项目目录 `logs/` 下保存有历史日志
4. 反馈时请附：操作步骤、错误文案、日志片段、系统配置
