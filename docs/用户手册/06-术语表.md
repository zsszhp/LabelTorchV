# 06 术语表

按界面出现顺序整理。左列为界面可见文案，右列为含义。

## 项目与数据

| 术语 | 说明 |
|------|------|
| **项目** | 一个缺陷检测任务的完整工作空间，包含数据集、类别体系、训练运行、模型与导出产物。项目数据保存在项目根目录 |
| **任务类型** | 项目能力范围：`detect`（目标检测）/ `obb`（旋转框检测）/ `classify`（图像分类）/ `anomaly`（异常检测） |
| **数据集** | 一批图片与对应标签的集合，支持 YOLO txt、COCO json、无标签图片三种导入形态 |
| **样本** | 数据集中的单条记录（一张图片 + 其标签） |
| **YOLO txt** | 标签格式：每行 `class_id cx cy w h`，坐标归一化到 0~1；OBB 为 `class_id x1 y1 x2 y2 x3 y3 x4 y4` |
| **类别体系（taxonomy）** | 项目的类别定义与顺序（class_id → 名称），版本化管理 |
| **类别映射** | 导入外部数据时，源标签类别顺序与项目类别体系之间的转换规则，可追溯历史修订 |
| **数据集标签（Tag）** | 用于数据集分类与筛选的自定义标记，与类别（class）不同，不参与训练 |
| **重复图** | 内容哈希相同的多张图片，导入/检查时可检出 |
| **跨划分泄漏** | 同一图片内容同时出现在训练集与验证集，会导致评估指标虚高，必须清理 |

## 数据冻结版

| 术语 | 说明 |
|------|------|
| **数据冻结版（snapshot）** | 训练数据的不可变副本记录，含样本清单与内容哈希。训练必须基于数据冻结版而非数据集实时状态 |
| **manifest** | 数据冻结版的清单文件，记录样本 ID、路径、内容哈希、train/val 划分 |
| **哈希冻结** | 创建冻结版时记录每个样本的内容哈希，训练前校验，不一致则拒绝或提示物化冻结副本 |
| **物化冻结副本** | 把冻结版数据物理拷贝到 `snapshots/{id}/`，保证源数据变更后训练仍用冻结内容 |
| **train/val 划分** | 训练集与验证集的比例划分，按样本 hash 分配，支持自定义比例与随机种子 |

## 训练

| 术语 | 说明 |
|------|------|
| **训练运行（training run）** | 一次训练任务的完整记录：配置、状态、日志、指标、失败诊断 |
| **模型家族** | 训练网络选型：yolov5 / yolov8 / yolov8-obb / yolov8-cls / yolov10 / yolov11 |
| **epochs** | 训练轮数 |
| **batch** | 批大小。显存不足时减半可显著降低占用 |
| **imgsz** | 输入图片尺寸。降低可提速并减少显存，代价是小目标检出率下降 |
| **AMP** | 自动混合精度训练，加速并降低显存 |
| **断点续训（resume）** | 从 `last.pt` 继续训练，loss 曲线衔接 |
| **训练适配器（TrainingAdapter）** | 训练框架插件接口，内置 Ultralytics 与 Anomalib 两种实现 |
| **失败诊断** | 训练失败时保留日志尾部 + 结构化建议（如「一键降 batch/imgsz」） |
| **epoch 指标（run_metrics）** | 每轮训练结束记录的 loss / mAP50 / mAP50-95 / precision / recall 等，用于绘制实时曲线 |

## 模型与评估

| 术语 | 说明 |
|------|------|
| **模型版本（model version）** | 一次训练产出的权重记录，可追溯到训练运行与数据冻结版；也支持外部导入 |
| **血缘（lineage）** | 模型 → 训练运行 → 数据冻结版的追溯链 |
| **基线版（baseline）** | 作为对比基准的模型版本标签 |
| **产线版（production）** | 已部署到产线的模型版本标签 |
| **mAP50 / mAP50-95** | 平均精度均值，IoU 阈值 0.5 / 0.5:0.95，越高越好 |
| **precision / recall** | 查准率 / 查全率 |
| **PR 曲线** | 查准率-查全率曲线，围成面积反映综合检出能力 |
| **混淆矩阵** | 各类别之间的误检/漏检分布 |
| **逐类指标** | 每个类别的 AP/P/R，用于定位薄弱类别 |
| **部署阈值推荐** | 基于评估结果推荐的 conf 阈值，附万件漏检/超检预估 |
| **Go / No-Go** | 是否达到产线 KPI 的结论判定 |
| **指标对比** | 多个模型版本横向（同数据不同配置）/ 纵向（增量训练链）对比 |

## 标注与辅助

| 术语 | 说明 |
|------|------|
| **HBB** | 水平边界框（Horizontal Bounding Box），即普通矩形框 |
| **OBB** | 旋转边界框（Oriented Bounding Box），带角度的矩形框 |
| **修订追踪** | 每次保存标注自动记录 before/after 快照，支持撤销与审计 |
| **辅助标注** | 用已有模型推理新图片生成候选框，人工审核确认后回写标签 |
| **难例挖掘（active learning）** | 把低置信、误检、漏检、难例样本收集为队列，优先人工审核，重启不丢 |
| **低置信队列** | 模型置信度低于阈值的预测结果 |
| **误检队列（false positive）** | 模型预测为正但实际为负的样本 |
| **漏检队列（false negative）** | 模型应检出但遗漏的样本 |
| **难例队列（hard case）** | 综合难度较高的样本 |

## 异常检测

| 术语 | 说明 |
|------|------|
| **异常检测（anomaly）** | 仅用正常样本训练，检出偏离正常分布的缺陷 |
| **异常热力图** | 叠加在图片上的异常区域可视化 |
| **AUROC** | 异常检测评估指标，受试者工作特征曲线下面积 |
| **image_auroc / pixel_auroc** | 图像级 / 像素级 AUROC |
| **Anomalib** | 异常检测训练框架，可选依赖（未安装时适配器自动跳过） |

## 导出与交付

| 术语 | 说明 |
|------|------|
| **pt** | PyTorch 权重格式，便于继续训练与 Ultralytics 生态使用 |
| **onnx** | 开放神经网络交换格式，部署常用 |
| **tflite / engine** | TensorFlow Lite / TensorRT 格式（预留） |
| **产物验证** | 导出后用 ONNX Runtime / TorchScript 校验产物可加载可推理，验证失败不可标记生产 |
| **交付目录** | 导出后自动生成：模型 + `classes.yaml` + `thresholds.json` + `warmup.py` + 推理样例 |
| **opset** | ONNX 算子集版本，影响兼容性 |
| **warmup.py** | 交付目录内的推理预热脚本，用于部署侧自检 |

## 系统与审计

| 术语 | 说明 |
|------|------|
| **审计日志（task_events）** | 关键不可逆操作的留痕记录：项目/数据集删除、导入、训练启停、导出等 |
| **IPC** | 主进程与 Python 后端之间的 stdin/stdout JSON-RPC 通信 |
| **训练适配器注册表** | 插件式注册训练框架的机制，第三方可扩展 |
| **绿色包** | 解压即用的免安装发行包，内嵌 Python 运行时 |
| **NaN 告警** | Debug 版布局引擎的浮点异常检测告警，超阈值建议保存重启，不影响数据 |
