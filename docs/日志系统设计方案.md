# LabelTorchV 日志系统设计方案 v1.0

> 状态：待确认
> 日期：2026-10-06
> 需求来源：异常捕获、闪退、系统占用、用户操作、信息监控——事后都要能在日志里查到

---

## 0. 需求决策记录（grill-me 访谈结论）

| 问题 | 决策 |
|---|---|
| 日志读者 | 自己/开发者排查问题，日志留本机即可，无报障回传需求 |
| 用户操作粒度 | 关键业务动作（页面切换、CRUD、任务启停），不做画布逐笔、不做全量点击 |
| 系统占用 | 周期采样（30s）+ 重操作启动时事件采样 + 阈值告警 |
| 闪退现场 | 全面增强：符号化调用栈 + 崩溃前日志黑匣子 + 会话信息 |
| 文件策略 | 按天 + 单文件 50MB 分卷，保留 14 天；崩溃目录限 20 份 |
| Release 默认级别 | INFO（关键动作/警告/错误全在，DEBUG 默认不落盘） |
| 查看方式 | 文件 + 「打开日志目录」入口；现有底部 LogPanel 保留 |
| Python 后端 | 独立按天日志文件，前端主日志保留 stderr 转发行 |

## 1. 现状盘点（已调研）

已有能力（本次在其上增强，不推倒重来）：

| 能力 | 位置 | 现状 |
|---|---|---|
| 消息处理器 | `src/core/utils/Log.cpp` | `qInstallMessageHandler` → stderr + 按天文件 `labeltorch_日期.log`，保留 7 天，`QLoggingCategory` 过滤 |
| 日志类别 | `src/core/utils/Log.h` | 14 个 `lt.*` 类别，全代码 831 处 `ltInfo/ltWarning/ltError` 调用 |
| 崩溃捕获 | `src/app/main.cpp` | `SetUnhandledExceptionFilter` → minidump(.dmp) + 摘要(.txt，仅异常码/地址)；`std::set_terminate`；NaN ASSERT 降级保护 + 前 3 次调用栈 |
| 任务审计 | `src/core/utils/AuditLog.cpp` | SQLite `task_events` 表，训练/导出/测试任务生命周期 |
| 后端捕获 | `src/core/ipc/IpcClient.cpp` | 后端 stderr 逐行转发为主日志 `[Python Stderr]`；`onBackendFinished` 记退出码 |
| UI 日志面板 | `src/shell/qml/LogPanel.qml` | 底部可折叠面板，2000 行环形缓冲，级别过滤；`Main.qml` 内已有 `logLevelCombo`（目前只影响面板显示，未接落盘级别） |

缺口（本方案补齐）：用户操作日志、系统占用采样、崩溃前黑匣子、崩溃摘要调用栈、崩溃目录清理、后端独立日志、级别持久化接线、日志目录入口。

## 2. 总体架构

```
                     ┌────────────────────────── C++ 前端 ──────────────────────────┐
  C++ 服务层 ──ltXxx──▶ qInstallMessageHandler 链                                      │
  QML console ───────▶  customMessageHandler(NaN过滤) → LogMessageHandler → Qt默认    │
                     │      │                    │                │                  │
                     │      │ 同步写(加锁+flush)  │                │                  │
                     │      ▼                    ▼                ▼                  │
                     │  stderr(控制台)      labeltorch_日期.log   黑匣子环形缓冲        │
                     │                      (按天+50MB分卷)    (预分配char,无锁,200条) │
                     │                                        │崩溃时                │
                     │  UserAction操作日志(lt.ui)              ▼                     │
                     │  SystemMonitor采样(lt.sys)        crash_时间戳.txt            │
                     │                                   (+.dmp minidump)            │
                     └───────────────────────────────────────────────────────────────┘
  Python 后端 ──logging──▶ logs/backend_日期.log(独立文件) + stderr → IpcClient转发主日志
```

原则：

1. **文件是唯一真相**：所有级别落盘规则只在 `Log` 一处控制；LogPanel/审计表是补充视图，不是另一份事实。
2. **崩溃路径零分配**：崩溃处理器内只用预分配缓冲和 Win32 API（沿用现有 minidump 代码的纪律）。
3. **埋点在 Service 层公共入口**，不在 QML 每个按钮上埋——改 UI 不丢日志，一条路径一处记录。

## 3. 日志分级与类别

### 3.1 级别

沿用 Qt 四档 + FATAL（崩溃）：`DEBUG / INFO / WARNING / ERROR / FATAL`。
`ltTrace` 保持为 `ltDebug` 的别名（Qt 类别只有四档，不引入假五档）。

### 3.2 类别（新增 2 个）

| 类别 | 用途 | 状态 |
|---|---|---|
| `lt.ui` | 用户操作日志 | **新增** |
| `lt.sys` | 系统占用/环境/监控 | **新增** |
| `lt.core/db/fs/ipc/project/taxonomy/dataset/annotation/training/model/inference/export/testing/app` | 既有模块 | 不动 |

### 3.3 级别控制（三处来源，优先级从高到低）

1. 环境变量 `LT_LOG_LEVEL`（debug/info/warning/error）——开发与自动化验收用；
2. 设置页下拉 `logLevelCombo` → 写入 `AppSettings`（新增 `logLevel` 键）→ `Log::setLevel`；
3. 默认值：**Release/INFO、Debug 构建/DEBUG**（`Log::init` 内按 `_DEBUG` 宏显式设置默认过滤规则，现状是 `lt.*=true` 全开，需改为按默认级别收敛）。

## 4. 文件策略

| 项 | 规则 |
|---|---|
| 目录 | `%LOCALAPPDATA%/LabelTorch/logs/`（`QStandardPaths::AppDataLocation`，现状不变）；`LT_LOG_DIR` 环境变量可覆盖 |
| 主日志 | `labeltorch_YYYYMMDD.log`；单文件超 **50MB** 关闭并另起 `labeltorch_YYYYMMDD_001.log` 递增分卷（消息处理器内检查字节数，加锁下进行） |
| 保留 | **14 天**（`cleanOldLogs` 的 7 改 14），启动时清理；分卷随日期前缀一起按修改时间清理 |
| 崩溃目录 | `logs/crash/crash_时间戳.dmp/.txt`；启动时只保留**最新 20 份**（补现状"永不清理"缺口） |
| 后端日志 | `logs/backend_YYYYMMDD.log`，Python `RotatingFileHandler`（50MB × 5 份），同样 14 天清理 |
| 行格式 | `[时间] [级别] [类别] [sid] 消息  [函数:行号]`；`sid` = 本次启动的短会话标识（如 `s103045`），同一天多次启动可在文件内区分会话；文件头额外写一行会话头（版本/Qt 版本/启动时刻） |

## 5. 用户操作日志（新增，`lt.ui`）

### 5.1 记录辅助

```cpp
// src/core/utils/UserAction.{h,cpp}（新文件，薄封装）
// 统一格式：action=<名> target=<对象> <k=v ...>
UserAction::log("dataset.import", datasetName, {{"count", 320}, {"cost_ms", 1204}});
// 落盘行示例：
// [INFO] [lt.ui] [s103045] action=dataset.import target=面板缺陷-03 count=320 cost_ms=1204
```

### 5.2 埋点清单（关键业务动作，全部在 Service 层/Controller 层入口）

| 模块 | 动作点 |
|---|---|
| 页面 | `AppController::setCurrentPage`：`from→to` |
| 项目 | 创建 / 打开 / 关闭 / 删除 / 重命名（`ProjectService`） |
| 数据集 | 导入（路径/数量/耗时）/ 删除（`DatasetService`） |
| 类别 | 类别体系增删改（`TaxonomyService`）、类别映射（`ClassMappingService`） |
| 标签 | Tag 增删改、快捷键打标（`TagService`） |
| 快照 | 创建（比例/策略）/ 删除（`SnapshotService`） |
| 标注 | 打开图片 / 保存提交（张数）/ 删除标注 / 批量操作（`AnnotationService`；画布逐笔不做） |
| 训练 | 创建 / 启动 / 停止 / 完成（含最终指标摘要）（`TrainingService`） |
| 推理 | 辅助标注启动 / 确认回写（张数）/ 异常检测启动（`InferenceService`、`AssistedLabelService`、`AnomalyService`） |
| 测试 | 评估任务创建 / 启动（`TestingService`） |
| 导出 | 导出启动 / 完成（`ExportService`） |
| 设置 | pythonPath / 日志级别等设置修改（`AppSettings` 写入口） |
| 生命周期 | 启动 / 正常退出（已有，保留） |

量级预估：常规使用每天数十~数百条，不刷屏。

## 6. 系统占用监控（新增，`lt.sys`）

### 6.1 新类 `SystemMonitor`（`src/core/utils/SystemMonitor.{h,cpp}`）

- **周期采样**：`QTimer` 30s 一条 INFO（约 2880 条/天，约 200KB/天，可接受）：

  ```
  sys_sample proc_mem_mb=412 proc_cpu_pct=8.3 disk_free_gb=118.2 db_size_mb=23.6 thumb_cache_mb=128.0
  ```

- **事件采样**：`sampleNow(reason)` 公共方法——训练启动/推理启动/导出启动时立即补一条，`reason` 标明触发源（Service 层调一行）。
- **阈值告警**：进程内存 > 85% 物理内存总量、磁盘剩余 < 5GB → 记 WARNING（同一越界状态只报一次，恢复后重置）。
- **启动环境快照**（INFO 一条）：CPU 核数、内存总量、OS 版本、磁盘剩余、GPU 名称（复用后端 `environment` handler 的信息或 WMI 查询）。
- Win32 实现：`GetProcessMemoryInfo` / `GetSystemTimes` / `GetDiskFreeSpaceExW`；CPU% 用两次采样差值。

## 7. 信息监控（运行状态，`lt.ipc` / `lt.sys`）

| 项 | 规则 |
|---|---|
| IPC 请求耗时 | `IpcClient` 请求发出→响应到达记耗时；> 3s 记 WARNING，其余 DEBUG（常态安静，排查时把级别调到 debug 可见） |
| 后端生命周期 | 补 `started` 日志；`onBackendFinished` 现有退出码日志增强：区分正常退出/崩溃（`crashed()`）+ 附最近一次发出的请求方法（帮助定位"点了什么之后后端挂了"） |
| 训练/推理里程碑 | epoch 完成等进度事件已有 `task_events` 审计，本方案不重复落文件日志，仅保证错误路径有 ERROR 行 |
| 不做 | DB 慢查询统计、JSON 格式、网络上报、日志加密（明确排除，避免过度设计） |

## 8. 崩溃与异常捕获增强（`main.cpp` + 新 `CrashReport`）

### 8.1 黑匣子环形缓冲（崩溃前日志快照）

- `main.cpp` 内静态预分配 `char ring[256][1024]` + 原子写索引；`LogMessageHandler` 格式化后同时拷入（截断保护）。
- 无锁、零堆分配、线程安全（每线程槽位或原子索引递增覆盖）。
- 崩溃过滤器 / terminate 处理器内把最近约 200 条按序 dump 进 `crash_*.txt`。

### 8.2 崩溃摘要 `.txt` 全面增强

现状只有异常码/地址，增强为：

1. **会话信息**：应用版本、Qt 版本、sid、启动时刻、已运行时长、NaN 累计计数；
2. **最后用户动作**：UserAction 侧另维护一个"最后 N 条操作"的轻量环形数组（与 8.1 同法），崩溃时一并写入——直接回答"闪退前用户在干嘛"；
3. **符号化调用栈**：崩溃线程 `CaptureStackBackTrace` + `SymFromAddr`（`dumpCallStackIfNeeded` 已有同款模式，抽成可复用函数）；解析失败退化为模块+偏移；
4. **已加载模块列表**：主程序/Qt/Python DLL 的路径与大小（辅助判断版本错配）；
5. **异常上下文**：寄存器快照、访问违例的读/写属性；
6. minidump（`MiniDumpNormal`）维持现状不变。

### 8.3 崩溃目录治理

- 启动时清理，只保留最新 20 份崩溃产物。
- `terminate` 处理器同样写黑匣子 + 调用栈（现在只写一行文字）。

### 8.4 后端闪退

`IpcClient::onBackendFinished` 已记退出码；增强为：`exitStatus == CrashExit` 时附最近 IPC 请求与运行时长，WARNING 级别必落盘。

## 9. Python 后端日志（`backend/labeltorch_backend`）

- `server.py` 的 `logging.basicConfig` 改为：`RotatingFileHandler(logs/backend_YYYYMMDD.log, 50MB×5)` **+ stderr 双输出**（stderr 保留，前端转发链不断）。
- 日志目录由前端传入：`IpcClient::startBackend` 在已有 `setProcessEnvironment` 处追加 `LT_BACKEND_LOG_DIR=<AppDataLocation>/logs`；后端读不到该变量时退回 stderr-only（兼容独立运行/测试）。
- 后端 14 天清理在 Python 侧启动时执行（同规则）。
- 训练/推理适配器的详细输出（ultralytics/anomalib 打印）随 logger 一并进文件。

## 10. 设置入口（`Main.qml`）

- **级别下拉接线**：`logLevelCombo`（Main.qml ~1800 行处，现只改 LogPanel 显示阈值）增加 `onActivated` → `Log::setLevel` + `AppSettings` 持久化；启动时 `Log::init` 读回。
- **新增「打开日志目录」按钮**（设置区旁）：`Qt.openUrlExternally(file:///...logs)`；C++ 侧经 `AppController` 暴露 `logsDir()` 属性，避免 QML 里拼 AppData 路径。
- LogPanel 保持现状（实时视图），文案注明"完整历史请看日志文件"。

风险与对策：

- **消息处理器性能**：每条日志加锁+flush 沿用现状（崩溃安全优先）；DEBUG 默认关闭后常态量可控。`LT_LOG_*()` 宏每次构造类别对象的现状保留（量小，不动 831 处调用点）。
- **崩溃路径安全**：只新增预分配缓冲操作与 Win32 调用；符号化失败不影响 minidump 落地。
- **QML 变更**：本方案 QML 只动 `Main.qml` 一处；注意 QML 嵌入资源需重新构建才生效。
