## 1. 文档目的

本文件用于锁定 LabelTorchV 当前阶段的 UI 复刻标准、复刻顺序、页面结构、视觉令牌、组件要求和接线策略，保证不同模型都能复现同一套界面，而不是各自发挥。

本文件的核心目标是：

1. 高保真复刻参考 HTML
2. 形成 Qt/QML 可维护的组件体系
3. 先做 UI 壳，再接真实数据，再补业务逻辑

---

## 3. 视觉总基调

根据 HTML 参考稿，当前 UI 的视觉语言锁定为：

1. 深色工业风
2. 冷调蓝灰主基底
3. 高亮青蓝色主强调
4. 细描边、轻阴影、弱发光
5. 信息密度偏高，但结构清晰
6. 桌面工具型，不走消费级卡通风

### 3.1 核心色彩

应优先对齐 HTML 中的设计变量：

- 主背景：`#0F131A`
- 侧栏背景：`#151A22`
- 卡片背景：`#1E2530`
- 输入背景：`#121720`
- 边框：`#262F3D`
- 主文本：`#E2E8F0`
- 次文本：`#64748B`
- 主强调：`#0077FF`
- 主发光：`#00E5FF`
- 成功：`#00E676`
- 危险：`#FF1744`
- 警告：`#FF9100`

Qt/QML 中允许按现有 `Theme.qml` 命名规范映射，但视觉效果要保持一致。

### 3.2 字体与密度

1. 字体优先使用 `Segoe UI` 与 `Microsoft YaHei`
2. 主字号以 `11px ~ 14px` 的紧凑桌面布局为基准
3. 标题更重，正文轻量，辅助说明更淡
4. 列表、配置面板、图表标题都采用紧凑布局

### 3.3 交互质感

必须统一提供：

1. hover 亮度提升
2. active 发光或底边高亮
3. selected 明确边框或底色反馈
4. disabled 透明度降低
5. error 使用红色强调
6. running 使用绿色或青色强调

## 4. UI 复刻的总顺序

任何模型执行 UI 复刻时，必须按下列顺序推进：

### 步骤 1：主题与组件基座

先建设：

1. 颜色与字体令牌
2. 通用按钮
3. 通用输入框
4. 通用下拉框
5. 通用卡片
6. 通用分组标题
7. 通用状态标签
8. 通用弹窗
9. 通用分割器
10. 通用图标组件

### 步骤 2：主框架

先搭：

1. 顶栏导航
2. 顶部过滤栏
3. 主内容容器
4. 左右侧栏骨架
5. 底部状态条或日志区

### 步骤 3：页面空壳

按页面逐个复刻视觉和布局，不急于接数据。

### 步骤 4：弹窗与上下文菜单

完成页面后再补：

1. 新建项目弹窗
2. 导入数据集弹窗
3. 新建模型弹窗
4. Tag 管理弹窗
5. 类别配置弹窗
6. 批量修改弹窗
7. 右键菜单

### 步骤 5：静态交互状态

补齐：

1. 折叠展开
2. 页签切换
3. 子页签切换
4. 高亮态
5. 加载态
6. 空态
7. 错误态

### 步骤 6：真实数据接线

用户确认 UI 架子方向后，再与 Service/Model 对接。

## 6. 页面级复刻要求

## 6.1 项目页

参考位置：HTML 中 `page-project` 区域。

必须包含：

1. 左侧项目管理栏
2. 主按钮“新建项目”
3. 次按钮“打开项目”
4. 右侧最近使用项区域
5. 项目卡片包含名称、路径、最近修改时间

验收标准：

1. 左右比例接近参考稿
2. 卡片 hover 反馈清晰
3. 主次按钮风格明显区分

## 6.2 数据集页

参考位置：HTML 中 `page-dataset` 区域。

必须包含：

1. 顶部过滤栏
2. 左侧图库选择
3. 数据集列表
4. 可见性、添加、导入图像等操作位
5. 数据集进度条与数量
6. 图像属性区
7. Tag 区
8. 中部画廊缩略图区

验收标准：

1. 面板分组和层次清晰
2. 列表项与卡片项状态风格一致
3. 缩略图区支持后续接入懒加载结构

## 6.3 标注页

必须包含：

1. 左侧数据集与类别区
2. 中部画布区
3. 画布顶部工具条
4. 右侧实例列表
5. 右侧文件列表

当前阶段要求：

1. 先做高保真外壳
2. 为未来画布能力保留足够空间
3. 快捷键和工具图标先做结构位

## 6.4 检查页

必须包含：

1. 结构上与标注页保持亲缘关系
2. 左侧保持数据选择与筛选能力
3. 主区域适配检查视图

## 6.5 训练页

参考位置：HTML 中 `page-train` 区域。

必须包含：

1. 左侧模型任务列表
2. 顶部子页签：`配置参数` 与 `实时训练结果`
3. 配置页采用四宫格结构：
   - 数据集配置
   - 网络配置
   - 训练设置
   - 数据增强配置
4. 结果页采用左状态栏 + 右图表区结构
5. 图表包含损失、mAP、召回率、精确率等位置

这是当前阶段最重要的页面之一，必须尽早接真实数据。

## 6.6 测试页

必须包含：

1. 左侧复用训练任务或模型选择区
2. 右侧测试配置
3. 统计卡区
4. PR 曲线区
5. 测试详情区
6. 混淆矩阵与检查图像双视图
7. 批量修改入口

当前阶段可以先完成 UI 壳，后续逐步接真实评估逻辑。

## 6.7 导出页

必须包含：

1. 左侧模型选择区
2. 右侧导出配置
3. 导出报告或验证报告区域
4. 导出参数位：格式、路径、目标平台、动态 shape、opset、simplify

该页面必须尽早接真实导出能力。

---

## 7. 弹窗规范

所有弹窗都要统一风格，包括：

1. 半透明遮罩
2. 深色卡片主体
3. 清晰标题区
4. 表单区紧凑对齐
5. 底部操作按钮区
6. 关闭按钮

必须优先支持的弹窗：

1. 新建项目
2. 打开项目
3. 导入数据集
4. 新建训练模型
5. Tag 编辑
6. 类别配置
7. 批量修改

---

## 8. 页面状态规范

每个页面必须考虑以下状态：

1. 空态
2. 加载态
3. 成功态
4. 失败态
5. 禁用态
6. 未选择项目态
7. 无设备态

这些状态必须在 UI 结构上提前预留，不允许后期硬塞。

---

## 9. UI 与真实数据接线原则

UI 进入接线阶段时必须遵守：

1. 页面状态由 Service/Model 驱动
2. 假数据逐步被真实数据替换
3. 所有按钮都必须有明确的禁用条件
4. 所有耗时动作都必须有进行中状态
5. 所有错误都必须能回显到用户界面

---

## 10. 当前阶段的 UI 验收标准

UI 达标需要同时满足：

1. 与参考 HTML 的页面骨架高度接近
2. 顶栏、侧栏、子页签、图表容器、弹窗风格统一
3. 组件具备复用能力
4. 后续接真实数据时无需大面积推翻重写

---

## 11. 当前建议的执行方式

1. 先建设基础组件与主题
2. 再复刻项目页、数据集页、训练页、导出页
3. 再补标注页、检查页、测试页
4. 用户确认 UI 架子后，再进入大规模真实功能填充
