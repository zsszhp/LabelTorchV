# 标炬（LabelTorch）技术栈决策记录 (Architecture Decision Record)

> 版本：2.0 | 更新日期：2026-05-31
> 状态：**已决策 — 选择路径 A：继续 Qt 6 + C++17 + QML**

---

## 一、 决策背景

项目开发过程中存在两条技术路径的争论：
1. **路径 A（现有代码库）**：基于 **C++ (Qt 6 / QML) + Python**，已完成了项目管理、数据库 DDL、IPC 通信协议、7 大功能模块的大部分 C++ 逻辑和 QML 界面。
2. **路径 B（新 PRD 建议）**：基于 **React + Electron / Tauri + Python**，需要全新编写前端代码。

---

## 二、 最终决策

### ✅ 选择路径 A：继续使用 Qt 6 + C++17 + QML

### 决策理由

#### 1. 现有代码资产保护
| 层级 | 规模 | 价值 |
|------|------|------|
| C++ Service 层 | 85 个源文件 / ~12,179 行 | 7 个功能模块全部有实现 |
| QML UI 层 | 35 个 QML 文件 / ~12,373 行 | 7 个页面 + Shell + Theme 完整 |
| Python 后端 | ~2,000 行 | IPC Server + 6 Handler + 2 Adapter |
| 数据库 Schema | 14 张核心表 | DDL 完整，数据迁移机制就绪 |

迁移到 Electron/React 意味着 **~24,500 行 C++/QML 代码全部废弃重写**，仅有 Python 后端 2,000 行可复用。

#### 2. MVP 接近完成
导入 → 训练 → 导出的核心闭环已基本通路，距离可发布的 MVP 仅需：
- 修复若干已知 Bug（路径硬编码、状态名不一致等）
- 集成测试
- 打包发布

#### 3. 工业场景契合
- **内存占用低**：Qt 应用 ~100-200MB vs Electron ~300-500MB+
- **启动速度快**：原生 C++ 冷启动 ~1-2 秒 vs Electron ~3-5 秒
- **4K 大图处理**：原生 GPU 渲染性能优于 Chromium Canvas

#### 4. Python 后端完全通用
JSON-RPC over stdin/stdout 的 IPC 设计与前端技术栈完全解耦，Python 后端代码一字不改即可服务于 Qt 或 Electron 前端。

## 四、 路径 A 开发约束

选择 Qt/C++ 路线后，需要遵守以下开发规范：

### 1. 框架限定
本项目是 C++17 + Qt 6.11 QML 的桌面程序，数据库为 QtSql (SQLite)，IPC 通信使用 QProcess。**禁止引入任何 Node.js、React、Vue 或 Electron 依赖。**

### 2. QML 模块约束
界面组件必须在 `src/features/` 下对应的 `qml/` 目录中开发，并确保每次修改后都在 CMake 中注册了对应的 QML 模块。

### 3. 主题系统约束
所有颜色/字体/间距使用 `Theme.xxx` 引用（`src/theme/Theme.qml`），**禁止在 QML 中硬编码颜色值**。

### 4. 画布标注方案（v1.0）
v1.0 标注功能使用以下技术方案实现：
- **渲染层**：`QQuickPaintedItem` + C++ QPainter 渲染，GPU 加速通过 Qt Scene Graph
- **交互层**：C++ `CanvasController` 管理缩放/平移/坐标变换/绘制模式
- **几何内核**：`AxisAlignedBox`（HBB）、`RotatedBox`（OBB）、`Polygon`（多边形）
- **性能优化**：大图（4K+）使用分层渲染——底层原图缩略渲染 + 顶层标注矢量渲染，确保拖拽帧率 ≥ 60fps

## 五、 后续开发防遗漏核对单 (AI 实施检查)

无论使用哪个 AI 工具开发，都必须避开以下常见工业算法工具的"暗坑"：

- [ ] **路径空格与中文**：YOLO 训练引擎底层是 PyTorch/C++，遇到中文路径经常报错。前台在导入数据集和创建项目时，必须正则校验路径，若有中文/空格需强制拦截提示。
- [ ] **训练卡死检测**：Qt 必须对 Python 子进程注册 `QProcess::finished` 信号监听，若非正常退出，必须立刻将页面上的"训练状态"置为"已中断/失败"，并弹出报错日志，不能让界面无限期处于"训练中..."的假死状态。
- [ ] **多张卡并发抢占**：在工控机上可能有多个显卡，或者有其他生产软件在占用 GPU。在配置界面中，必须让用户显式选择设备（如 `cpu`, `cuda:0`, `cuda:1`），而不是在后台写死 `cuda`。
- [ ] **大图片（4K+）标注卡顿**：工业相机拍摄的图片多为高分辨率。如果直接将原图加载到画布中，拖拽会极其卡顿。`QQuickPaintedItem` 应使用分层渲染和离屏缓存策略，确保交互流畅。
- [ ] **Python 进程 stdout 阻塞**：启动 Python 子进程时，必须设置 `PYTHONUNBUFFERED=1` 环境变量，防止标准输出缓冲区满导致 Python 进程假死。
