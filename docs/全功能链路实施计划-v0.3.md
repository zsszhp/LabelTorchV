> 制定日期：2026-10-01

## 0. 产品愿景与验收基准

**标炬 LabelTorch** = X-AnyLabeling 级别的标注工作台 + 工业级训练评估闭环（参考 Dihui 类页面的训练管理）。

验收基准（每批实施后必须逐条核对）：

1. 零崩溃：任意顺序点击全部 14 个页面（8 主导航 + 6 孤页），运行日志无 ReferenceError / TypeError / Cannot read / 无法锚定。
2. 空态可达：未打开项目时，所有导航可点击，每页呈现引导空态而非禁用/空白/报错。
3. 链路自证：以自生成示例数据，真实走通 导入→标注→冻结→训练→评估（混淆矩阵/PR）→导出 onnx→辅助标注，留截图与日志证据。
4. 视觉一致：全站无白底默认控件，无霓虹彩虹残留，遵循 Apple HIG 风格令牌（Theme.qml 单一来源）。
5. 测试门禁：ctest 24/24 + pytest 48/48 全绿后方可提交。

## 2. 演示模式设计（未开项目也能看功能）

### 2.1 产品行为
1. **首次启动**（projects 表为空）：自动创建「示例项目」并打开——内含自生成合成缺陷数据集（12 张 640×480 合成工业图像 + YOLO 标签 + 3 类别：划痕/凹陷/污染）+ 预置标签体系（默认/良品/漏检/误检/待定/重要）。
2. **非首次**：项目页侧栏提供「载入示例项目」按钮（已存在则直接打开），保证任何时候一键可看全部功能。
3. **导航解锁**：去掉未开项目时的禁用逻辑，所有页面永远可点；需要项目上下文的页面显示统一引导空态（EmptyState：说明 + 「新建项目」「打开项目」按钮直达）。

### 2.2 技术方案
- 示例图像经 CMake `qt_add_resources` 打进 exe（`assets/demo/`），首次运行解压到 `%AppData%/LabelTorch/demo/`。
- `AppController::ensureDemoProject()`（Q_INVOKABLE）：幂等——检测同名项目存在则直接返回其 id；否则经 ProjectService/DatasetService/TaxonomyService/TagService 全链路真实创建（不走 SQL 直插，保证与 UI 创建完全同构）。
- main.cpp：引擎加载后若 projects 为空自动调用；项目页按钮手动调用。
- E2E 自动化钩子沿用 LT_DEBUG_OPEN_PROJECT / LT_DEBUG_PAGE，另增 LT_DEBUG_AUTO_SNAPSHOT=1（自动创建冻结版）。

### 2.3 空态审计与守卫
放开导航前必须逐页核对（子 agent 审计 + 人工复核）：
- Component.onCompleted / onVisibleChanged 的 projectOpen 守卫齐全；
- C++ 服务对空 projectId 的行为（返回空而非异常）；
- 每页补齐「未打开项目」EmptyState（含直达按钮）。

## 3. E2E 全链路自证方案（本机 CPU 可行版）

数据：示例项目 12 图 3 类。模型：yolov8n。参数：epochs=5、imgsz=320、batch=4、device=cpu（预计数分钟）。

| 步骤 | 动作 | 证据 |
|------|------|------|
| E1 | 启动→自动建示例项目→打开 | 项目页截图 |
| E2 | 标注页自动载入首图→人工/脚本绘制标注→自动保存 | 标注页截图+标签文件 |
| E3 | LT_DEBUG_AUTO_SNAPSHOT=1 创建冻结版 | 快照页截图+DB 记录 |
| E4 | 训练页启动 CPU 训练→实时曲线→完成 | 训练中/完成截图+训练日志 |
| E5 | 测试页对 best 权重评估→混淆矩阵/PR/Go-NoGo | 测试页截图 |
| E6 | 导出 onnx→验证通过→模型版本 | 导出页截图+产物文件 |
| E7 | 辅助标注用导出模型回灌推理 | 智能辅助页截图 |
| E8 | 全程日志零错误归档 | 日志文件留存 |

实施说明：E4 起每步可通过 LT_DEBUG 钩子自动触发；训练时长用小参数控制；若 CPU 过慢则降 epochs=3。

## 5. 分工（多 agent 协作）

| 角色 | 任务 | 方式 |
|------|------|------|
| 主控（本会话） | 架构决策、核心编码、集成、提交 | 直接实施 |
| 审计agent-作用域 | QML 中间层属性非限定引用扫描 | Explore agent / 脚本化扫描 |
| 审计agent-样式 | 白底控件与硬编码色值扫描 | 同上 |
| 空态agent | 无项目状态逐页安全性审计 | Explore agent |
| 对标agent | X-AnyLabeling 标注能力差距清单 | Explore agent |
| 测试agent | ctest/pytest/运行时日志三重门禁 | 主控执行+留证 |

> 并发额度受限时，审计类任务回退为主控脚本化扫描（grep 管线 + 人工判定）。

## 6. 风险与对策

| 风险 | 对策 |
|------|------|
| CPU 训练过慢 | 降 epochs/imgsz；必要时仅验证训练启动+前几步曲线 |
| 放开导航引发新空指针 | 空态审计先行+守卫补齐+日志门禁 |
| 示例资源膨胀 | 合成 PNG 控制在 1MB 内；不入 git 的构建产物一律忽略 |
| 服务创建链路绕过 UI 校验 | ensureDemoProject 全部走 service 公共 API，不走直插 SQL |
