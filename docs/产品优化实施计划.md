# LabelTorch 产品优化实施计划

> 版本：1.0
> 日期：2026-06-08
> 状态：待确认
> 依据：19 角色联合侦查报告（产品/UI/UX/前端/后端算法/QA/安全/性能/DevOps/文档/架构/Qt稳定性/FAE/项目管理/数据治理/交互微体验/算法产品）

---

## 1. 已确认的四项方向决策

| 决策项 | 结论 |
|--------|------|
| 本期主目标 | **稳定性收口优先**，冻结新功能，集中修崩溃/数据安全/假实现 |
| 页面范围 | **收敛并修复孤页**，导航降到 7~8 页 |
| 快照策略 | **哈希冻结 + 按需物化**（manifest 记 hash，训练前校验，必要时物化冻结副本） |
| 计划形式 | **分阶段实施计划**：P0 紧急修复 → P1 体验与功能 → P2 交付与治理 |

---

## 2. 现状总评

| 维度 | 评分 | 说明 |
|------|------|------|
| 功能闭环 | 65/100 | 项目→导入→训练→导出骨架可用，多项假实现 |
| 稳定性 | 55/100 | 闪退风险：跨线程 DB、后端无限重启、无崩溃捕获 |
| UI/UX | 70/100 | 高保真工业风，但假控件、孤页、反馈缺失 |
| 数据可信 | 50/100 | 快照不可变、审计链、类别删除均未真正落地 |
| 交付就绪 | 28/100 | 绿色包跑不起来，版本号分裂 |
| 测试保障 | 40/100 | C++ 服务层较扎实，E2E/UI/适配器零覆盖 |

**核心矛盾**：用户诉求「绝不能闪退、开箱即用」优先级最高，但历史投入以新功能为主，稳定性投入约 <25%。本计划将投入结构倒转。

---

## 3. 范围边界（本期明确不做）

为保证稳定性收口见效，以下一律进入 backlog，不在本期实施：

1. 新增页面、新模型家族（SAM、RT-DETR 等）
2. 多人协作、任务分配、云端同步
3. TensorRT / TFLite / Engine 完整导出闭环（仅补验证，不扩格式）
4. Ubuntu 交付级兼容
5. 主动学习算法升级（仅修「确认后回写标签」闭环，不加新策略）
6. 视频推理性能优化（仅保证不崩，不做实时流）
7. 浅色主题、多语言界面
